# 개발 가이드

## 환경 요구사항

| 도구 | 버전 |
|------|------|
| Node.js | **20 (LTS Iron)** — `nvm use lts/iron` |
| pnpm | 최신 (corepack 또는 `npm i -g pnpm`) |

> Vitest 4.x는 Node 20+ 필수입니다. Node 18에서는 `styleText` export 오류로 실행되지 않습니다.
> 훅(`check-commit-sequence.sh`)은 커밋 시 자동으로 `nvm use lts/iron`으로 전환합니다.

## 명령어

```bash
cd webapp

pnpm dev          # 개발 서버 (포트 3010, Turbopack)
pnpm build        # 프로덕션 빌드
pnpm lint         # ESLint
pnpm test         # 전체 테스트 1회 실행 (Vitest)
pnpm test:watch   # Vitest watch 모드

# 단일 테스트 파일 실행 (webapp/ 디렉터리 안에서 실행)
pnpm vitest run src/lib/__tests__/sort.test.ts

# Web Adventure 콘텐츠 lint
pnpm lint:web-adventure              # 본문 길이/문단 lint (#248)
MONGO_URI=... pnpm lint:web-adventure:structure   # 그래프 구조 lint (#271)

# Playwright e2e (#277)
pnpm e2e:install                                  # chromium 다운로드 (1회)
PLAYWRIGHT_BASE_URL=http://localhost:3010 pnpm e2e
```

## 작업 규칙

- **테스트를 먼저 쓴다.** 구현 전에 실패하는 테스트를 쓰고 **빨강을 눈으로 확인**한 뒤
  구현한다. 통과하는 테스트를 나중에 덧붙이면 그 테스트가 무엇을 잡는지 알 수 없다 —
  실패하는 것을 본 적이 없기 때문이다.
- **빨강을 봤다는 증거를 남긴다.** PR 본문에 실패했을 때의 테스트 출력을 붙인다.
  TDD 는 "했다"고 말하기 쉽고 확인하기는 어렵다. 증거가 없으면 검수에서 반려한다.
- 작업 완료 전 테스트 스위트를 실행해 통과를 확인한다.
- `webapp/src/lib/*` 로직은 단위 테스트, API 동작은 API 수준 테스트를 선호한다.
- **목(mock)으로 확인할 수 없는 것은 실제로 재본다.** DB 질의의 의미, 브라우저 동작,
  권한 규칙처럼 **틀려도 조용히 지나가는** 것들이 있다. 대조군을 두고 전후를 비교한다.
  (실제로 그렇게 새어 나간 것들: 배열 필드의 `$not` 의미, 셸 변수가 든 명령의 권한 거부,
  게인 노드가 없어 음량 조절이 무효였던 것.)
- **못 잡는 테스트는 없는 것보다 나쁘다** — 있다고 착각하게 만든다. 그래서 통과를 봤으면
  한 번 더 묻는다: *이 테스트가 정말 실패할 수 있나?* 의심스러우면 구현을 잠깐 틀리게
  고쳐 빨강을 확인한다. (실제로 새어 나간 것: 조상 선택자가 엉뚱한 요소를 재서 그냥
  통과한 폭 단언 — #443.)
- **구조가 아니라 행동을 단언한다.** DOM 구조·내부 상태·클래스 이름에 걸면 리팩터링마다
  깨지고, 정작 기능이 망가진 건 못 잡는다. e2e 선택자 규칙과 강건성 항목은
  [webapp/e2e/README.md](../webapp/e2e/README.md) 에 있다.
- **순수 모듈은 변이 시험으로 단언의 무름을 감사한다.** `pnpm test:mutation`
  (`webapp/stryker.config.mjs`, 주 1회 CI). 커버리지는 "실행됐나"만 보므로 결과를 단언하지
  않은 코드가 초록으로 남는다. 살아남은 변이 = 빈 단언. 데이터·바깥 경계는 범위에서 뺀다
  (콘텐츠 숫자를 베껴 적는 시험은 밸런스를 만질 때마다 깨진다).
- 아키텍처에 영향을 주는 변경은 `docs/` 내 관련 문서를 업데이트한다.

## 설계 취향

거창한 패턴보다 아래 넷이 이 저장소에서 실제로 값을 냈다. 새 코드도 여기에 맞춘다.

- **순수/부수효과 경계를 먼저 긋는다.** 규칙은 `lib/**` 순수 함수로, 네트워크·DOM·시계는
  바깥에. 그러면 같은 코드를 시험과 실행이 공유하고, 검증이 브라우저 없이 밀리초로 끝난다
  (에테르니아: 순수 206개 **0.75초** vs e2e 24개 **27초**).
- **얕은 모듈 여러 개보다 깊은 모듈 몇 개.** 파일을 잘게 쪼갤수록 "무엇이 실제로 실행되는가"를
  알기 위해 열어야 할 파일이 는다. 구현체가 하나뿐인 인터페이스, "나중을 위한" 추상층,
  테스트만을 위한 seam 은 만들지 않는다 — 그건 순수 함수로 빼는 게 답이다.
- **주석은 "왜"를 측정값과 함께 적는다.** `MAX_GAP = 40` 은 왜 40인지 없어서 다시 재야 했고,
  오각형에 달린 "남는 공간을 적이 채운다" 한 줄은 그것이 placeholder 임을 즉시 알려 줬다.
  상수·임계값·우회에는 그 숫자가 어디서 나왔는지 남긴다.
- **중복된 사실은 타입으로 강제한다.** 유니온·enum 을 한 곳에 두면 빠진 분기를 컴파일러가
  짚는다. 규율로 지키는 것보다 기계가 지키는 것이 오래간다.
