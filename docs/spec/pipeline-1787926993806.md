서버 상태를 게임 메뉴 바로 아래 평탄한 항목으로 옮긴다

요청 스레드 6a8fb4688b6e602e662d41ea. 지금 "서버 상태" 는 게임 메뉴 안의 "에테르니아의
추락" 하위에 있다. 이것을 게임 메뉴 바로 아래 평탄한 항목으로 올린다. owner 전용은
그대로 둔다.

**이 스펙은 메뉴 이동 하나만 다룬다.** 캡처와 이미지 업로드는 별건이고 이 브랜치에 넣지
않는다. 앞선 두 실행이 그 둘을 한 스펙에 섞었다.

**무엇을 고치나**

`webapp/src/components/navbar.tsx` 의 `gameLinks` **데이터만** 바꾼다. JSX 는 한 줄도
고치지 않는다.

지금 서버 상태는 `gameLinks[0]`(에테르니아의 추락)의 `children[3]` 이다
(`navbar.tsx:78-85`). 이것을 빼내어 `gameLinks` 의 **새 최상위 항목**으로 올리고, 그
항목의 `children` 에 서버 상태 하나만 둔다.

새 항목의 값:

- `key` — `server-status`
- `label` — `서버 상태`
- `description` — `로컬 LLM/서버 상태 (읽기 전용)`
- `icon` — 이미 import 되어 있는 `Server`
- `children` — 항목 하나. `href: "/scenes/status"`, `label: "서버 상태"`,
  `description: "로컬 LLM/서버 상태 (읽기 전용)"`, `icon: <Server size={20} />`,
  `authOnly: true`, `ownerOnly: true`

**자리는 `gameLinks` 의 맨 끝**이다. 앞에 끼우면 `mobileOpenGameKey` 초기값이
`gameLinks[0]?.key` 라(`navbar.tsx:167`) 모바일 기본 펼침 대상이 바뀐다.

**왜 JSX 를 안 고쳐도 되나**

`only` 패턴이 데스크톱과 모바일 양쪽에 이미 있다 — `navbar.tsx:243`, `navbar.tsx:443`.
하위가 하나뿐인 묶음은 게임 이름 자체가 그 항목의 링크가 된다. 그래서 새 묶음은 펼침
토글이 아니라 평탄한 링크로 그려지고, 화면에 나오는 글자는 `game.label`("서버 상태"),
`href` 는 `only.href`("/scenes/status")가 된다.

owner 전용도 그대로 지켜진다. `visibleChildren` 이 `ownerOnly` 를 거르고
(`navbar.tsx:172-175`), 남은 항목이 0개인 묶음은 `visibleGames` 가 통째로 뺀다
(`navbar.tsx:177`). owner 가 아니면 새 묶음의 유일한 하위가 걸러져 묶음이 사라진다.

라우트는 안 옮긴다. `/scenes/status` 그대로다. `middleware.ts` 도 안 건드린다 —
`/scenes/` 프리픽스가 이미 덮는다.

**앞선 두 실행이 왜 멈췄나 — 같은 함정을 피할 것**

같은 스펙이 8/28 21시 37분과 22시 29분에 **빨강 게이트(UNEXPECTED_PASS)** 에서 멈췄다.
그때 쓴 테스트가 이렇게 시작한다.

    // Phase E 이후: quest CMS UI/API 일괄 제거에 따라 navbar 의
    // questLinks 드롭다운 + 모바일 collapsible 도 사라졌다.

이 두 줄은 기존 `webapp/src/components/navbar.test.tsx` 의 16-18줄을 **그대로 옮긴
것**이다. 그 파일의 단언까지 같이 베껴 왔고, 그 단언들은 오늘도 통과한다. 그래서 구현
없이 초록이 떴고 게이트가 옳게 거부했다. 고장이 아니라 테스트가 틀렸다.

그러므로 이번에는:

- 새 파일 하나만 만든다 — `webapp/src/components/navbar.game-menu-status.test.tsx`
- 기존 `navbar.test.tsx` 는 **관행만** 본다. mock 거는 방식과 세션 위장 방식만 가져오고
  **단언은 한 줄도 베끼지 않는다.**
- 기존 `navbar.test.tsx` 를 **고치지 않는다.** 고치면 그 파일이 이번 스펙의 테스트 목록에
  들어가고(`pipeline.mjs:466`), 이미 통과하는 스무 건 남짓 때문에 빨강 게이트가 즉사한다.
- 새 파일에 넣는 단언은 **전부 오늘 실패해야 한다.** 오늘 이미 참인 것은 넣지 않는다.
  예를 들어 "비owner 에게 서버 상태가 안 보인다" 는 오늘도 참이라 넣으면 안 된다 —
  그건 기존 `navbar.test.tsx:51` 과 `:171` 이 이미 덮고 있고, 초록 게이트의 전체 스위트가
  지킨다.

**껍데기는 만들지 않는다**

이번엔 새 모듈이 없다. 고칠 것이 이미 있는 `navbar.tsx` 의 데이터뿐이라 테스트가 import
할 대상이 이미 존재한다. 껍데기를 만들면 오히려 오염이다.

**테스트 — 오늘 반드시 실패하는 것들**

환경은 jsdom 지정 주석을 첫 줄에 둔다. 세션 위장은 기존 관행을 따른다
(`navbar.test.tsx:1-14`, `:234-239`) — `vi.mock('next-auth/react')` 로 `useSession` 을
가짜로 두고 `data.user.isOwner` 를 준다. `usePathname` 도 같이 가짜로 둔다.

owner 세션(`isOwner: true`, `status: 'authenticated'`) 기준으로:

1. 데스크톱 — `게임 메뉴` 를 열기만 하면 `서버 상태` 링크가 바로 있고 `href` 가
   `/scenes/status` 다. 오늘은 `에테르니아의 추락 하위 메뉴` 를 더 눌러야 나오므로 실패한다.
2. 데스크톱 — `에테르니아의 추락 하위 메뉴` 를 펼쳤을 때 **그 묶음 안에는** 서버 상태가
   없다. 최상위의 서버 상태 링크와 섞이면 안 되므로, 그 토글의 `closest('li')` 안으로
   범위를 좁혀서 본다(`navbar.tsx:246` 이 `<li key={game.key}>` 로 감싼다). 오늘은 그 안에
   있으므로 실패한다.
3. 데스크톱 — 에테르니아 하위 항목이 셋이다. 플레이·씬·피드백 노트. 오늘 넷이라 실패한다.
4. 모바일 — `모바일 메뉴 열기` 와 `모바일 게임 섹션 토글` 만으로 `서버 상태` 링크가 있고
   `href` 가 `/scenes/status` 다. 오늘은 `모바일 에테르니아의 추락 토글` 을 더 눌러야
   하므로 실패한다.
5. 모바일 — `모바일 에테르니아의 추락 토글` 을 펼쳤을 때 그 묶음 안에 서버 상태가 없다.
   오늘 있으므로 실패한다.
6. 데스크톱 — `pathname` 이 `/scenes/status` 일 때도 최상위 서버 상태 링크가 그대로 있다.
   활성 표시(글자색)만 달라지고 사라지면 안 된다. 오늘은 애초에 최상위에 없으므로 실패한다.
7. 데스크톱 — 새 묶음은 펼침 토글을 만들지 않는다. `게임 메뉴` 를 연 뒤 게임 드롭다운
   직속에 무엇이 놓이는지를 한꺼번에 재고, 거기에 에테르니아 토글 하나와 `/games/retro`
   링크와 `/scenes/status` 링크가 있다고 단언한다. `only` 가 새 묶음에서 실제로 잡혔는지를
   재는 단언이다. 오늘은 `/scenes/status` 가 없어서 실패한다.

경계에서 더 볼 것:

- 데스크톱 마크업과 모바일 마크업이 한 화면에 같이 그려질 수 있으므로, 모바일 단언은
  `getAllByRole` 로 받아 `href` 로 걸러 세는 기존 관행을 따른다(`navbar.test.tsx:186-190`).
- 고전 게임 묶음은 하위가 하나뿐이라 이미 `only` 로 그려진다. 새 묶음을 더한 뒤에도
  고전 게임이 여전히 `/games/retro` 링크로 남아 있어야 한다. 이것만 따로 단언하면 오늘도
  통과하므로, 위 7번 안에 함께 넣어 그 단언 전체가 오늘 실패하게 만든다.

  구별하지 못한다는 신호다. "요소를 못 찾음" 과 "개수가 다름" 이 섞여야 한다.

  `navbar.test.tsx:51` 과 `:171` 의 비owner·비로그인 단언이 깨지면 owner 전용이 샌 것이다.
- 전체 스위트가 초록이어야 한다.
