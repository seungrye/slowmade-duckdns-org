에이전트 호출이 한 번 실패했다고 파이프라인을 끝내지 않는다

배경 (실측)

두 밤 연속으로 파이프라인이 1회차에서 죽었다. 둘 다 원인은 같다 — OpenRouter 업스트림
제공자의 일시적 429 다.

    opencode 로그 5273-5285 줄 (2026-08-28T18:39:49 ~ 18:40:23Z)
    error.error="AI_APICallError: [GMICloud] minimax/minimax-m3:free is temporarily
    rate-limited upstream. Please retry shortly, ..."

opencode 자신이 다섯 번 재시도하고(2.3초·4.6초·9초·17.6초 간격, 총 34초) 포기한 뒤
0 이 아닌 코드로 끝났다. 그 순간 파이프라인은 `salvage` 로 가고 `process.exit(2)` 로
끝난다. 모델은 은퇴하지 않았고 자격증명도 네트워크도 멀쩡하다 — 잠깐 막힌 것뿐이다.

두 가지가 잘못돼 있다.

1. `pipeline.mjs:272` 의 `stdio: ['ignore','inherit','inherit']` 때문에 실패 이유가
   보고에 안 실린다. `e.message` 는 노드가 만든 "Command failed: <명령줄>" 뿐이라,
   스레드 덧글에 명령줄과 프롬프트만 찍히고 왜 죽었는지가 없다. 두 밤 다 사람에게
   "모델·자격증명·네트워크를 먼저 보세요" 라는 **추측**만 전달됐다.
2. `pipeline.mjs:277` 이 첫 실패에서 바로 끝낸다. `DEV_MODELS` 에 개발자가 둘 있는데
   1회차는 늘 `DEV_MODELS[0]` 이고(`pipeline.mjs:310`) 그것이 죽으면 둘째는 불려 보지도
   못한다. 유닛에 3시간이 잡혀 있는데 34초 만에 포기한 셈이다.

함수 1 — retryPlan({ attempt, models, maxAttempts })

이번 시도에 무엇을 어떻게 부를지 정한다. 그만둘 때가 됐으면 null.

인자
- `attempt` — 1부터 세는 시도 번호. 1 이 첫 시도다
- `models` — 이번 호출에 쓸 수 있는 모델 목록. 앞에 있는 것부터 쓴다.
  모델 인자가 없는 에이전트(클로드)는 `[null]` 을 넘긴다
- `maxAttempts` — 총 시도 상한. 안 주면 3

반환 `{ model, waitMs }` 또는 `null`

규칙
- `models` 가 배열이 아니거나 길이가 0 이면 `null`
- `attempt` 가 정수가 아니거나 1 미만이면 `null`
- `maxAttempts` 를 줬는데 정수가 아니거나 1 미만이면 `null`. 안 줬으면 3 을 쓴다
- `attempt` 가 `maxAttempts` 보다 크면 `null`
- `model` 은 `models[(attempt - 1) % models.length]` — 목록을 순환한다
- `waitMs` 는 이 표 그대로다. 첫 시도는 안 기다리고, 그다음은 30초에서 두 배씩,
  300000 에서 멈춘다

      attempt   1       2       3       4        5        6        7
      waitMs    0   30000   60000  120000   240000   300000   300000

  식으로는 `attempt === 1 ? 0 : Math.min(300000, 30000 * 2 ** (attempt - 2))`

함수 2 — failureTail(chunks, limit)

실패한 시도가 뱉은 것들을 보고에 실을 한 덩이로 만든다.

인자
- `chunks` — 문자열 조각 배열. `e.stdout`·`e.stderr`·`e.message` 를 그대로 담아 넘긴다
- `limit` — 남길 글자 수. 안 주면 4000

반환 문자열

규칙
- `chunks` 가 배열이 아니면 `''`
- `limit` 을 줬는데 정수가 아니거나 1 미만이면 `''`
- 배열 안에서 문자열이 아닌 항목(null·undefined·숫자·객체)은 건너뛴다
- 남은 것을 **구분자 없이** 순서대로 잇는다
- 이은 길이가 `limit` 이하면 그대로 준다. 아무 표시도 붙이지 않는다
- 넘으면 **뒤쪽** `limit` 자만 남기고 그 앞에 `…(앞부분 생략)\n` 을 붙인다.
  즉 반환값 길이는 `limit + 10` 이 된다(표시가 10자)

배선 — pipeline.mjs

`runAgent` 의 서명을 바꾼다.

    runAgent(cmd, argsFor, who, worktree, models = [null])

- `argsFor` 는 `(model, attempt) => string[]` 이다. 모델이 바뀌면 인자도 바뀌어야 해서
  배열이 아니라 함수를 받는다
- 시도 루프를 돈다. 매 번 `retryPlan({ attempt, models })` 를 묻는다
  - `null` 이면 `salvage({ kind: StuckKind.AGENT_FAILED, who, output: 마지막출력 })`.
    `마지막출력` 은 직전 실패에서 `failureTail` 로 만든 것이다
  - `waitMs` 가 0 보다 크면 그만큼 동기로 잔다.
    `Atomics.wait(new Int32Array(new SharedArrayBuffer(4)), 0, 0, waitMs)`
    기다린다는 것을 `log` 로 남긴다 — 몇 초 뒤 어느 모델로 다시 부르는지 적는다
  - `sh(cmd, argsFor(plan.model, attempt), { cwd: worktree, stdio: ['ignore','pipe','pipe'] })`
  - 성공하면 받은 문자열을 `process.stdout.write` 로 그대로 내고 루프를 벗어난다
  - 실패하면 `failureTail([e?.stdout, e?.stderr, e?.message])` 로 만들어 두고, 그것을
    그 자리에서 화면에도 낸다. `attempt` 를 하나 올리고 계속한다
- `assertRepoClean(before, who)` 는 루프를 벗어난 뒤 한 번만 부른다

출력을 실시간으로 흘려보내던 것은 잃는다. 대신 **시도 하나가 끝날 때마다 그 시도의
출력을 통째로 낸다** — 삼키지 않는다는 원칙은 지켜지고, 실패 이유가 보고에 실린다.
지금은 그 이유가 systemd 저널에만 있어서 아침에 사람이 볼 수 없다.

호출부

- `claude(worktree, message)` — `models` 를 안 넘긴다(기본 `[null]`).
  `argsFor` 는 모델을 무시하고 지금 인자를 그대로 만든다
- `coder(worktree, message, round)` — 이번 회차의 당번을 맨 앞에 두고 나머지를 뒤에
  붙인 목록을 넘긴다

      const i = (round - 1) % DEV_MODELS.length;
      const models = [...DEV_MODELS.slice(i), ...DEV_MODELS.slice(0, i)];

  회차 교대는 지금과 똑같이 유지되고(1회차는 여전히 `DEV_MODELS[0]`), **첫 시도가
  죽었을 때만** 다음 개발자로 넘어간다.
  이어가기 `-c` 는 `attempt === 1` 이고 `DEV_MODELS.length === 1` 이고 `round > 1`
  일 때만 준다. 재시도에서는 절대 주지 않는다 — 모델이 바뀌면 그 세션이 아니다
- `manager(worktree, message)` — `[MANAGER_MODEL]` 을 넘긴다. 관리 후보를 늘리지 않는다.
  같은 모델로 0초·30초·60초 세 번이면 일시적 429 는 넘어간다

넣을 단언 스무 개 — 오늘 왜 실패하나

`agent-retry.mjs` 가 아직 없으므로 import 부터 터진다. 그 뒤 하나씩 의미를 갖는다.

retryPlan
1. 첫 시도는 첫 모델과 대기 0 을 준다
2. 둘째 시도는 둘째 모델과 30000 을 준다
3. 모델이 하나뿐이면 둘째 시도도 그 모델이다 — 대기만 붙는다
4. 모델 수보다 시도가 많아지면 목록 처음으로 돌아온다(셋째 시도가 첫 모델)
5. `maxAttempts` 를 넘는 시도는 `null`
6. 대기는 300000 에서 멈춘다 — 여섯째와 일곱째가 둘 다 300000
7. `models` 가 빈 배열이면 `null`
8. `models` 가 배열이 아니면(문자열·undefined) `null`
9. `attempt` 가 0 이거나 음수면 `null`
10. `attempt` 가 정수가 아니면(1.5) `null`
11. `maxAttempts` 를 안 주면 3 이 기본이다 — 셋째는 값이 나오고 넷째는 `null`
12. `maxAttempts` 가 0 이면 `null`
13. `models` 가 `[null]` 이어도 `model` 로 `null` 을 그대로 돌려준다.
    모델 인자가 없는 에이전트를 그렇게 부른다

failureTail
14. `limit` 이하면 그대로 준다 — 생략 표시가 붙지 않는다
15. `limit` 을 넘으면 뒤쪽 `limit` 자만 남고 앞에 `…(앞부분 생략)\n` 이 붙는다.
    남은 뒷부분이 원문의 마지막 `limit` 자와 정확히 같은지 함께 잰다
16. 길이가 정확히 `limit` 이면 생략 표시가 없다 — 경계에서 안 붙는다
17. 문자열이 아닌 항목은 건너뛴다 — `['가', null, undefined, 3, {}, '나']` 가 `'가나'`
18. 빈 배열이면 `''`
19. 배열이 아니면 `''`
20. `limit` 이 0 이거나 음수면 `''`

어떻게 확인하나

- 빨강 — 새 파일의 단언이 전부 실패한다. 첫 실행은 모듈을 못 찾아 전부 같은 이유로
  실패할 텐데, 그건 정상이다. 껍데기(`export function retryPlan() { throw ... }`)를
  두어 함수별로 다른 자리에서 실패하게 만든다
- 초록 — 새 파일이 전부 통과하고 `webapp/src/lib/ai-team/` 의 기존 테스트 열여섯 개가
  그대로 통과한다
- lint — 만들어 놓고 안 쓰는 import 가 없어야 한다. `no-unused-vars` 가 error 다
  (`eslint.config.mjs:32`). 특히 `failureTail` 을 `pipeline.mjs` 에서 실제로 부르는지
  확인할 것 — import 만 해 놓고 `e.message` 를 그대로 쓰면 이 건은 아무것도 고치지
  못한 것이다
- 검수에서 볼 것 — `runAgent` 가 정말 루프를 돌고 있는가. `retryPlan` 을 부르되
  반환값을 무시하고 한 번만 실행하는 모양이면 통과시키지 말 것
- 전체 스위트가 초록이어야 한다
