# 모델 순위를 주 1회 측정한다

관련: #305, #301

## 왜

`model-pick.mjs` 는 목록 조회로 **은퇴**를 잡지만, "목록에는 있는데 느리거나 못 하는"
경우는 못 잡는다. 그건 실제로 돌려 봐야 안다.

## 오늘 겪은 함정이 설계를 정한다

후보 5개를 재서 셋이 실패했는데, **원인이 능력이 아니라 무료 일일 한도 소진**이었다.

```
z-ai/glm-5.2:free    Rate limit exceeded: free-models-per-day
minimax-m3:free      OK
```

그대로 순위에 반영했으면 멀쩡한 모델 셋이 영구 강등됐을 것이다. 그래서 **못 잰 것과 못
하는 것을 반드시 구분**한다.

| 결과 | 뜻 | 순위 |
|---|---|---|
| `pass` | 게이트 초록 | 빠른 순으로 위 |
| `skip` | 한도·도달 불가 — **재지 못함** | 이전 순위를 유지한 채 pass 뒤 |
| `fail` | 돌았는데 초록 실패 | 맨 뒤 |

`skip` 을 `fail` 로 치면 한도 한 번에 좋은 모델이 밀려난다.

## 만들 것

| 파일 | 하는 일 |
|---|---|
| `scripts/ai-team/ranking.mjs` | `rankResults` · `readRanking` — 순수 |
| `scripts/ai-team/bakeoff.mjs` | 후보를 실제로 돌려 결과를 남긴다 |
| `ai-team-bakeoff.service` · `.timer` | 주 1회 |

`model-pick.mjs` 는 순위 파일이 **신선하면** 그 순서를, 없거나 낡았으면 코드의 기본 순서를
쓴다. 측정이 멈춰도 러너는 계속 돈다.

## 수용 기준

- `pass` 는 빠른 순으로 앞
- `skip` 은 pass 뒤, **이전 순위 순서를 지킨다** — 한도 때문에 강등되지 않는다
- `fail` 은 맨 뒤
- 후보에 없던 id 가 결과에 있어도 무시한다
- 순위 파일이 없거나·깨졌거나·오래됐으면 `null` — 호출측이 기본 순서로 떨어진다
- 위 전부 네트워크·파일 없이 도는 vitest 로 덮는다
