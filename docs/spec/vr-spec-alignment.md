## VR 을 원문 규격에 맞춘다 (#345)

라오어 VR 방법론 **원문 카페글**(방법론 개요·백테스트 3부작·인출식VR 등)과 우리 구현을
한 줄씩 대조했다.

## 먼저 — 핵심 수식은 맞다

가장 미묘한 지점이 정확히 맞춰져 있었다.

- 원문: *"이번 사이클이 끝나고 V = 9000$, pool = 1000$ 인 상태였다"* → *"다음V = 현재V +
  1000/10 + 250 = 9350"* → **V 는 CF 반영 _전_ pool 로 계산**
- 원문: *"적립**후** pool 의 75%", "인출**후** pool 의 25%"* → **한도는 CF 반영 _후_ pool**

구현이 `advanceCycleVR` 에서 이 둘을 갈라 쓴다. `V₂=V₁+Pool/G±CF`·밴드 `V(1±0.15)`·매매
3규칙·매도 평단 무관·첫 V=매수 직후 평가금도 모두 원문 그대로다.

## 원문 백테스트를 재현한다

거치식·TQQQ·2011~2020·±15% 로 원문 표와 대조(`vr-reference.test.ts`):

| G | CAGR 우리/원문 | MDD 우리/원문 | 평균 P/V 우리/원문 |
|---|---|---|---|
| 10 | 47.41 / 49.47 | −61.17 / −58.41 | 0.1459 / 0.1521 |
| 20 | 44.85 / 46.16 | −57.17 / −55.72 | 0.2663 / 0.2725 |
| 30 | 42.45 / 44.12 | −54.15 / −52.48 | 0.3669 / 0.3780 |
| 40 | 40.34 / 41.86 | −51.69 / −50.03 | 0.4533 / 0.4672 |

TQQQ 올인 MDD 가 −69.92% 로 **원문과 소수점까지 일치** — 같은 데이터라는 뜻이다.

차이는 **전부 한 방향**이다(우리가 수익 낮고·낙폭 크고·현금 얇다). 원인은 하나로 설명된다 —
원문은 **1주씩 지정가 사다리**로 장중 체결하는데 우리는 종가에 한 번에 산다. 비싸게 사면
Pool 을 더 쓰고 → P/V 가 낮아지고 → 상승률이 작아져 → 수익↓·낙폭↑. 즉 우리 백테스트는
**일관되게 보수적으로 과소평가**한다. 사다리는 별건으로 남긴다.

## 고친 것

**① Pool 한도·G 를 운용 형태에서 유도** — 원문 7.1 표(적립 10/75% · 거치 10/50% ·
인출 20/25%). 예전엔 `poolLimitPct` 가 늘 0.5 라 **적립식인데 거치식 한도로 돌았다.**
원문이 "가이드일 뿐이며 선택 가능" 이라 했으므로 설정에 적으면 그 값이 이기고, **안 적었을
때만** 형태를 따른다.

**② 실효평단을 낸다** — 원문 4.2 `(누적매수 − 누적매도) / 보유수량`. `cumBuy`·`cumSell` 을
수식대로 쌓아 두고도 결과에 안 실었다. 마이너스가 되면 원문 4.3 의 "원금 ZERO 상태"다.

**③ 손익 이름을 갈랐다** — `totalPnl` 이 전략마다 뜻이 다르다. 무한매수·로테이션·듀얼모멘텀은
**매도 실현손익 합계**, VR·변동성타깃은 **최종자산 − 투입원금(평가손익 포함)**. 같은
「실현손익」으로 부르면 전략끼리 비교가 어긋나서, 화면이 이름을 갈라 붙인다.

## 확인 불가 — 원문이 유료로 이동

cover-sell(인출충당 매도) 대금이 그 사이클 `Pool/G` 에 섞여 V 를 올리는 문제. 인출식 원문이
*"자세한 방법설명 및 중계는 팬딩에서 진행하게 됩니다"* 로 끝나, 공개 자료에서 얻을 수 있는
것은 **G=20 · Pool 25% 한도까지**다. 동작을 바꾸지 않고 주석으로만 남긴다.

## 2026-10-05 원저자 자료 재대조 (#533·#534)

원저자 자료(`/mnt/qnap-download/투자`, md 88개 — VR 학습·4/6/7기 운용 분석)와 다시 대조했다.

### 계산 계층은 고칠 것이 없다 — 원문 표로 재현

6기 23주차 원문을 구현 코드에 그대로 넣어 돌렸고 **센트 단위까지 일치**했다:

| 항목 | 원문 | 코드 |
|---|---|---|
| 다음 V(실력공식) | 1435.25 | 1435.25 |
| 밴드 | 1219.96 ~ 1650.54 | 동일 |
| 매수 6행 | 71.76 / 67.78 / 64.21 / 61.00 / 58.09 / 55.45 | 전부 일치 |
| 매도 5행 | 97.09 / 103.16 / 110.04 / 117.90 / 126.96 | 전부 일치 |

`V + P/G + (E−V)/(2√G) + C`, P 는 적립 전, 매수한도는 적립 후 Pool 기준, `E=수량×종가`,
밴드 ±15%, 사다리 `하단÷n`·`상단÷n` — 전부 맞다.

### 고친 것

1. **사이클 경계 V 갱신이 주문 실패에 묻혔다** — `sendOrders` 가 `saveState` 보다 먼저라,
   전량 거부로 throw 하면 그 사이클 갱신이 버려졌다. **2026-09-30 에 실제로 발생**
   (로그엔 `사이클 경계: V→$7,285.08`, 상태엔 `sinceCycle:9, V:6895.15`). → 저장을 앞으로.
2. **`cumBuy` 가 취득원가가 아니었다** — 기존 보유 채택 시 `수량×현재가`를 깔아 실효평단이
   실계좌에서 +9.6% 과대. → 증권사 평단이 있으면 `holding×avg`, 없으면 폴백 + 로그.
3. **실효평단을 라이브 요약에 싣는다** — 원문이 매주 쓰는 지표인데 백테스트에만 있었다.
4. **사이클 경계를 달력으로** — 실행 횟수는 결손·실패 런에서 경계가 **영구·누적** 이동한다.
   `isCycleDue`·`nextCycleAnchor`·`cycleCalendarDays`(전부 순수).
   - `cycleDays` 는 **실행일 단위**다 → 달력일로 환산(10 → 14). 안 하면 V 갱신이 40% 잦아진다
   - 앵커 없는 옛 상태는 `sinceCycle` 로 **역산해 시드** — 안 하면 배포 첫 런이 이른 경계를 터뜨린다
   - 앵커는 **격자에 맞춰** 전진(`anchor + days×floor(경과/days)`) — 실행일로 당기면 기어간다

### 설정으로 고칠 것 (코드 아님)

**VR 블록 `runAt` 10:50 → 09:40 ET.** 원문은 「**장개시**, 지정가, 기간잔량, 2주」다
(중계 정리:63 · 4기&6기 흐름 검토:177 · 4기 개요:17 — "기간잔량" 29건 전부 같은 방향).
10:50 이면 **09:30~10:50 80분간 주문이 없다.**

저장소에 10:50 을 정당화하는 기록은 **0건**이고 코드 기본값은 `09:35`(미장)다.
리비전 이력이 방치를 말한다: `v1 15:50`(LOC 컷오프 시절) → **43분 뒤** `v2 10:50`
(09:55 ET 에 55분 뒤를 찍음) → 이후 7회 수정에 한 번도 안 건드림.

09:35 가 아니라 **09:40** 인 이유: 같은 계좌의 `infinite_v4` 가 09:35 이고, `tradingTick` 이
포트폴리오를 순차 실행하며 `throttle()` 이 호출당 ≥1초를 직렬화한다 — VR 사다리 13~24건
(~25초)과 겹치면 뒤가 밀린다. 파이썬 저장소가 문서화한 "10분 분리" 관행을 따른다.
부수로 `scheduler.ts` 가 적어 둔 EST 00:50 KST 익일 경계 위험도 사라진다.

### 기각한 것 — 왜 안 고치는가

| 제기 | 기각 이유 |
|---|---|
| 배당금 Pool 미반영 | 규칙은 실존하나 원저자 실보고가 **4기 89주 합계 $24.55**(연 0.3~0.4%). 주문표가 바뀌는 최소액이 $148(실제의 20배). 제안했던 "cash−pool 차이 감지"는 **공유 계좌에서 차이 $86,929** → 가짜 경보. `pool` 은 블록별 장부지 계좌현금이 아니다 |
| Pool 마름 경고 | 백테스트엔 이미 있고 라이브도 매일 Pool 을 요약에 찍는다. 제안 조건을 라이브 규모로 실측하니 **경계 47/251(19%) 발화** — 잡는 건 고갈이 아니라 주당가격 양자화 |
| 인출식 G=20 이 근거 없음 | **오판이었다.** 새 자료(4·6·7기)는 전부 적립식이라 **인출식을 안 다룬다**. 자료 부재지 반박이 아니다. 7.1 표 값 유지 |
| 본장 기준(After 장 제외) | 원문 문장은 **중계표 동기화 지시**고 우리는 중계표를 안 따른다. 애초에 시간외 체결이 불가능하다(정규장 TR 00/34 뿐). `ord_tmd` 는 주문시각이라 세션 판정 불가 |

### 기록해 둘 교훈

**"내가 본 자료에 없다" ≠ "근거가 없다".** 인출식 G=20 을 "임의값" 이라 했다가 철회했다 —
커밋된 스펙(`vr-spec-alignment.md`)과 **테스트가 인용한 출처**를 먼저 봤어야 했다.

**「매일 취소 후 재등록」도 사실이 아니었다.** 운영 49런 전 전략에서 `묵은 주문 취소` 는
**0건** — KIS 미체결 지정가는 장 마감에 소멸해 지울 게 없다. 공백의 원인은 늦은 발주 하나다.
취소 로직을 건드리는 방향은 전부 헛수고다.

**기간잔량(GTC)은 KIS OpenAPI 에 수단이 없다**(`ORD_DVSN` 00/34 뿐). 사이클 내 사다리는
**가격 비의존**이고(V 고정) 매일 같은 표를 복원하므로, 일일 재등록이 유일하고 충분한
에뮬레이션이다 — 체결 기회를 줄이지 않는다. **시각만 틀렸다.**
