# `<<wait>>` 와 `<<set>>` 를 실제로 동작시킨다 — 문단 단위 순수 함수로

## 배경

`webapp/src/lib/web-adventure/script.ts:7` 주석은 렌더러가 `sfx/bgm/fx/img/wait/set` 을
제자리에서 실행한다고 적어 두었다. 그런데 실제 렌더러
`webapp/src/app/games/web-adventure/play/SceneRenderer.tsx` 는 `fx`·`sfx`·`bgm`(:186-201)과
`img`(:263)만 다룬다. `wait` 과 `set` 은 `parseScript` 가 분해만 하고 아무도 읽지 않는다.
주석이 구현보다 앞서 있었다.

이번 건은 그 둘을 동작시킨다. **상태를 늘리지 않는다** — 본문에 적혀 있는 것이라 씬을 받은
순간 전부 계산할 수 있다. `useState` 도 새 prop 도 만들지 않는다.

## 만들 것 — 순수 함수 둘

`webapp/src/lib/web-adventure/script.ts` 에 export 두 개를 **추가**한다. 기존
export(`interpolate`, `parseScript`, `ScriptSegment`)의 시그니처와 동작은 그대로 둔다.

### 1. `varsByParagraph(body, base?)`

    export function varsByParagraph(
      body: string[],
      base?: Record<string, string | number>,
    ): Array<Record<string, string | number>>

문단 i 가 보간에 쓸 변수 묶음을 문단마다 하나씩 돌려준다.

- 문단 i 의 값 = `base` 에 문단 0..i 의 `<<set …>>` 를 순서대로 얹은 것
- **`set` 이 든 문단 자신부터** 새 값이다. 문단 안 어디에 적혀 있든 그 문단 전체가 새 값을 본다
- 반환 배열의 길이는 `body.length`
- 각 원소는 서로 독립된 객체다. `base` 를 변형하지 않고, 원소끼리 참조를 공유하지 않는다

`<<set 키 값>>` 규칙:

| 입력 | 결과 |
|---|---|
| `<<set 이름 카엘>>` | `이름` = `"카엘"` |
| `<<set 이름 카엘 하이든>>` | `이름` = `"카엘 하이든"` — 남은 인자를 공백 하나로 잇는다 |
| `<<set 이름>>` | 무시. 키를 만들지 않는다 |
| `<<set>>` | 무시 |
| 같은 키를 두 번 | 뒤엣것이 이긴다 |
| `<<setup 이름 카엘>>` | `set` 이 아니다. 무시 |

값은 늘 문자열로 담는다. 숫자로 바꾸지 않는다 — `interpolate` 가 `String()` 으로 찍으므로
결과가 같고, 바꾸면 `"007"` 이 `7` 이 된다.

### 2. `revealSchedule(body, stepMs)`

    export function revealSchedule(body: string[], stepMs: number): number[]

문단 i 가 열릴 시각(씬 진입 기준 밀리초)을 문단마다 하나씩 돌려준다.

- 문단 0 은 항상 `0`
- 문단 i = `i * stepMs + (문단 0..i-1 의 wait 합)`
- 반환 배열의 길이는 `body.length`

`<<wait 값>>` 규칙:

| 입력 | 더해지는 값 |
|---|---|
| `<<wait 600>>` | 600 |
| 한 문단에 `<<wait>>` 가 여럿 | 전부 더한다 |
| `<<wait>>` — 인자 없음 | 0 |
| `<<wait abc>>` | 0 |
| `<<wait -500>>` | 0 |
| `<<wait Infinity>>` | 0 |
| `<<waiting 600>>` | `wait` 이 아니다. 0 |

한 줄로 떨어진다 — `const v = Number(args[0]); const ms = Number.isFinite(v) && v > 0 ? v : 0`.

**마지막 문단의 wait 은 아무 데도 안 쓰인다.** 뒤에 열릴 문단이 없기 때문이다. 그래도
오류가 아니다.

## 고칠 것 — 렌더러

`webapp/src/app/games/web-adventure/play/SceneRenderer.tsx`

### 1. 문단별 변수 (`:171-174`, `:261`)

지금 `bodyVars` 는 `useMemo` 하나로 씬 내내 고정이다. 문단 번호가 안 들어간다. 그래서
`set` 을 여기 얹으면 **이미 그려진 앞 문단까지** 새 값으로 다시 그려진다.

`bodyVars` 는 그대로 두고 그것을 `base` 로 삼아 `varsByParagraph(scene.body, bodyVars)` 를
`useMemo` 로 뽑는다. `:261` 의 `parseScript(p, bodyVars)` 를 그 배열의 i 번째로 바꾼다.
`useMemo` 의존은 `scene.body` 와 `bodyVars`.

### 2. 문단별 예약 (`:141-153`)

`window.setInterval(…, STEP_MS)` 하나를 `revealSchedule(scene.body, STEP_MS)` 로 건
`setTimeout` 여럿으로 바꾼다.

- 스킵 분기(`:141-144`)는 그대로 둔다. `skipAll`·`skipSequential`·`total === 0` 이면
  `setRevealCount(total)` 하고 타이머를 아예 걸지 않는다
- 문단 0 은 예약 없이 즉시 `setRevealCount(1)` 로 연다(지금 `:145` 와 같다). 나머지 i 는
  `schedule[i]` 에 `setRevealCount(i + 1)`
- **cleanup 에서 걸어 둔 타이머를 전부 걷는다.** 지금은 `clearInterval` 하나면 됐지만 이제
  배열을 돌아야 한다. 빠뜨리면 본문을 눌러 스킵한 뒤 몇 초 지나 앞 문단이 훅 지나온다.
  `skipAll` 이 이미 의존 배열(`:153`)에 있어 스킵 순간 effect 가 다시 돌고 cleanup 이
  불린다 — 걷는 코드만 있으면 그 경로가 닫힌다

### 3. 낡은 주석 (`script.ts:7`)

이제 참이 된다. 다만 `wait`·`set` 은 나머지와 성질이 다르므로 한 줄 덧붙인다 — **`set` 은
그 씬 안에서만 살고 `character.variables` 를 건드리지 않는다. 회차를 넘겨야 하는 값은
`Scene.onEnter.setVars` 로 쓴다**(`reducer.ts:154`, `types/web-adventure.ts:57`).

## 테스트

두 파일 다 **이미 있는 디렉터리**에 새로 만든다. 새 디렉터리를 만들면 안 된다 — 통째로
untracked 인 디렉터리는 `git status --porcelain` 이 한 줄로 접어서 파이프라인이 테스트를
못 본다(`pipeline.mjs:115`).

### `webapp/src/lib/web-adventure/script-timeline.test.ts`

`varsByParagraph` 와 `revealSchedule` 을 덮는다. 위 두 표의 칸이 각각 한 케이스다. 더해서:

- 빈 `body` → 둘 다 `[]`
- `set`·`wait` 이 하나도 없는 본문 → `varsByParagraph` 의 모든 원소가 `base` 와 같은 내용이고
  `revealSchedule` 은 `[0, stepMs, 2*stepMs, …]`
- `varsByParagraph` 가 `base` 를 변형하지 않는다 — 호출 뒤 `base` 를 다시 재서 그대로인지 본다
- 원소끼리 참조를 공유하지 않는다 — 한 원소에 키를 넣어도 다른 원소가 안 바뀐다
- 한글 키(`<<set 침식_손 3>>`)가 실제로 치환된다 — `parseScript(문단, 결과[i])` 를 거쳐
  표시 텍스트를 확인한다
- `stepMs` 가 0 이어도 wait 은 그대로 쌓인다

### `webapp/src/app/games/web-adventure/play/SceneRenderer.paragraph-vars.test.tsx`

`set` 이 렌더러에 **실제로 물렸는지**를 잰다. 테스트 환경은 `skipSequential` 이 참이라
(`:116`) 문단이 한꺼번에 그려지므로 문단별 값이 그대로 눈에 보인다.

케이스는 둘만 둔다. 각 케이스는 **오늘 반드시 실패해야 한다.**

1. 본문 `["{{이름}}", "<<set 이름 카엘>>{{이름}}", "{{이름}}"]` 을 한 블록에서 잰다 — 첫
   문단은 `{{이름}}` 이 원문으로 남고, 둘째와 셋째는 `카엘` 이다. 오늘은 둘째·셋째가 원문으로
   남아 실패한다. `character.variables` 에 이미 있는 키를 `<<set>>` 이 덮는지도 이 블록 안에
   함께 넣는다
2. 씬을 갈아 끼우면 값이 사라진다 — 위 씬을 그린 뒤 본문이 `["{{이름}}"]` 인 다른 씬으로
   rerender 하면 원문 `{{이름}}` 이다. 앞 씬에서 `카엘` 이 보였다는 단언을 같은 블록에 함께
   두어 오늘 실패하게 만든다

따로 떼면 오늘도 통과하는 단언이 섞인다. 그래서 한 블록에 묶는다.

**wait 은 단위 테스트로 못 잰다.** 테스트 환경이 `skipSequential` 로 타이머를 통째로
건너뛰기 때문이다. `revealSchedule` 순수 함수로만 덮고, 렌더러에 물렸는지는 검수에서 본다.

## 어떻게 확인하나

- **빨강** — 두 새 파일의 모든 케이스가 실패한다. `script-timeline.test.ts` 는 함수가 없어
  전부 실패하고, 렌더러 파일은 값이 안 바뀌어 실패한다. 어느 하나라도 구현 없이 통과하면
  그 케이스는 아무것도 구별하지 못하는 것이니 지운다
- **초록** — 두 새 파일이 전부 통과하고 기존 `script.test.ts`·`SceneRenderer.test.tsx` 도
  그대로 통과한다. 전체 스위트가 초록이어야 한다

## 검수에서 볼 자리

테스트만 겨우 통과하고 실제로는 안 고쳐진 모양이 이 건에서 둘 있다.

1. **순수 함수 둘만 만들고 렌더러를 안 건드린 경우.** `script-timeline.test.ts` 는 초록인데
   화면은 그대로다. 렌더러 테스트가 `set` 쪽은 잡지만 `wait` 쪽은 못 잡는다.
   `SceneRenderer.tsx` 에서 `window.setInterval` 이 사라지고 `revealSchedule` 이 실제로
   불리는지 눈으로 확인해야 한다
2. **cleanup 에서 타이머를 다 안 걷는 경우.** 테스트가 이 경로를 안 지난다. `useEffect` 의
   return 이 예약한 id 를 **전부** 지우는지 본다
