# 야간 러너를 1시간 주기로 — 겹치면 종료 직후 1회만

관련: #299

## 왜 시각이 아니라 경과인가

`OnCalendar=hourly` 로는 안 된다. 유닛이 `Type=oneshot` 이고 아직 activating 인 동안
타이머가 elapse 하면 systemd 가 같은 종류의 start job 을 **기존 job 에 합쳐 버린다** —
그 트리거는 사라진다. 90분짜리 실행이면 01:00 트리거가 없어지고 02:00 에야 다시 돈다.

그래서 타이머는 자주 깨우고(10분마다), **러너가 스스로 "지난 시작 이후 주기가 지났나" 만
본다.** 안 지났으면 즉시 종료.

- 90분 실행이 끝난 뒤 첫 깨움에서 이미 주기가 지났으므로 **바로 돈다**
- 밀린 횟수 개념이 없다 — **경과만 본다.** 3시간이 걸렸어도 다음은 1회
- 도는 중의 깨움은 systemd 가 병합/무시하고, 무시돼도 다음 깨움이 잡는다

## 만들 것 — `scripts/ai-team/interval.mjs`

| 내보내는 것 | 하는 일 |
|---|---|
| `DEFAULT_INTERVAL_SEC` | 3600 |
| `parseStamp(text)` | 기준 시각 파일 내용 → epoch 초. 못 읽으면 `null` |
| `shouldRun({now, last, intervalSec})` | 돌아야 하나 |

CLI 로도 쓴다: 돌아야 하면 **기준 시각을 지금으로 갱신하고** exit 0, 아니면 exit 1.
`run.sh` 가 맨 앞에서 이걸 부르고 exit 1 이면 조용히 끝낸다.

기준 시각은 **시작 시점**에 찍는다(종료가 아니라). 주기가 start-to-start 가 되어야
3시간짜리 실행 뒤에 곧바로 다음이 돈다.

## 수용 기준

- 기준이 없으면(첫 실행) 돈다
- 경과가 주기와 **정확히 같으면** 돈다. 1초 모자라면 안 돈다
- 기준 파일이 깨졌으면(빈 값·문자·음수) 돈다 — 나쁜 파일 하나로 영영 멈추면 안 된다
- 기준이 **미래**여도 돈다 — 시계가 어긋났거나 파일이 잘못된 것이지, 막을 이유가 아니다
- 주기가 0 이하거나 숫자가 아니면 기본값(3600)으로 본다
- 위 전부 파일·시계 없이 도는 vitest 로 덮는다
