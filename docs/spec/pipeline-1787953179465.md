캡처가 메뉴를 펼친 뒤 찍게 한다

무엇이 문제인가

"서버 상태 메뉴를 게임 메뉴로 옮기고 데스크톱·모바일로 캡처해 보여 달라" 는 요청이
있었다. 메뉴 이동 구현은 브랜치에 있고 캡처 통로도 이미 있다. 그런데 찍어도 그 메뉴가
화면에 안 나온다.

네비바 드롭다운은 hover 가 아니라 클릭으로 열린다. 데스크톱은 게임 버튼의 onClick 이
상태를 뒤집고(webapp/src/components/navbar.tsx:232), 모바일은 햄버거(:394)를 누른 뒤
게임 섹션 토글(:425)을 또 눌러야 한다. hover 클래스는 글자색만 바꾼다.

scripts/ai-team/shot.mjs 는 page.goto 직후 바로 page.screenshot 을 한다(:91, :102).
클릭하는 단계가 없다. 그래서 지금 찍으면 접힌 네비바만 나오고 서버 상태 항목은
데스크톱·모바일 어느 쪽에도 없다. 메뉴 이동 브랜치를 배포해도 캡처로 확인할 수 없다.

무엇을 만드나

shot.mjs 에 --menu 옵션을 더한다. 주면 그 메뉴를 뷰포트에 맞게 눌러 펼친 뒤 찍는다.

클릭할 대상은 뷰포트마다 다르다. 그래서 인자로는 논리 이름을 받고 뷰포트별 aria-label
순서로 번역한다. 번역표가 순수 규칙이라 테스트로 덮는다.

논리 이름 "게임" 의 데스크톱 순서는 ["게임 메뉴"] 하나다.
모바일 순서는 ["모바일 메뉴 열기", "모바일 게임 섹션 토글"] 둘이다.

세 라벨은 실제 마크업에 있는 것이다 — navbar.tsx:233, :395, :426.

이번에는 "게임" 하나만 넣는다. 주식·마이페이지 메뉴에는 지금 aria-label 이 없어 같은
방식으로 못 잡는다. 모르는 이름을 주면 거절한다.

어디를 고치나

순수 규칙은 scripts/ai-team/shot-args.mjs 에 둔다. 테스트가 여기를 잰다.

1. MENUS 를 export 한다. 논리 이름에서 desktop·mobile 두 목록으로 가는 표다. 위 내용
   그대로. 같은 파일의 SIZES 관행대로 Object.freeze 로 얼린다(:13).
2. parseShotArgs 가 --menu 이름 꼴을 받는다.
3. clickPlan(menu, sizeName) 을 새로 export 한다. 그 뷰포트에서 누를 라벨을 순서대로
   담은 새 배열을 낸다.

브라우저를 모는 얇은 부분은 shot.mjs 에 둔다. 테스트 대상이 아니다.

4. 뷰포트마다 clickPlan 결과를 받아 그 순서대로 page.getByLabel(라벨).click() 한다.
   상태 토글이라 애니메이션은 없지만 리렌더를 기다리게 클릭 사이에 짧게 쉰다.
5. 라벨을 못 찾으면 멈춘다. 조용히 접힌 화면을 찍어 올리면 사람이 잘못된 것을 보고
   판단한다. 세션이 안 붙었을 때 멈추는 기존 가드와 같은 취지다(shot.mjs:95-101).

반드시 지킬 것

기존 webapp/src/lib/ai-team/shot-args.test.ts:10 이 경로 하나만 준 결과를 toEqual 로
재는데, 기대값이 path·owner·port 셋뿐이다. 그러므로 --menu 를 안 주면 결과에 menu 키를
담지 않는다. 빈 문자열이나 null 을 넣어도 그 단언이 깨진다. 옵션이 없으면 필드도 없다.

기존 shot-args.test.ts 는 한 줄도 고치지 않는다.

경계에서 어떻게 동작하나 — 이것이 곧 테스트다

새 파일 webapp/src/lib/ai-team/shot-menu.test.ts 에 쓴다. import 는 기존 파일과 같은
관행을 따른다.

parseShotArgs 쪽

1. 경로와 --menu 게임 을 주면 menu 가 "게임" 이고 path·owner·port 는 그대로다.
2. 경로만 주면 결과에 menu 키가 아예 없다. in 연산자로 잰다 — toEqual 로는 값이
   undefined 인 키가 가려져 이 규칙이 안 걸린다.
3. --menu 뒤에 값이 없으면 null 이다.
4. --menu 뒤가 --owner 면 다음 인자를 값으로 삼키면 안 되므로 null 이다.
5. MENUS 에 없는 이름을 주면 null 이다.
6. --menu 를 두 번 주면 null 이다. 한 번만 받는다.
7. --menu 와 --owner 는 순서를 바꿔 줘도 같은 결과다.
8. --menu 와 --port 는 함께 쓸 수 있다. --owner 와 --port 를 함께 못 쓰는 기존
   제약(shot-args.mjs:53)은 --menu 와 무관하다.

clickPlan 쪽

9. "게임" 과 desktop 이면 라벨 한 개짜리 목록이다.
10. "게임" 과 mobile 이면 햄버거가 먼저고 게임 토글이 나중인 두 개짜리 목록이다.
    순서가 뒤집히면 안 된다 — 햄버거를 먼저 눌러야 안쪽 토글이 화면에 있다.
11. menu 가 undefined 면 빈 목록이다. 모바일에서도 빈 목록이다 — 햄버거를 자동으로
    누르지 않는다.
12. 모르는 이름이면 빈 목록이다. 던지지 않는다.
13. 낸 목록을 바꿔도 MENUS 가 안 바뀐다. 두 번 불러 서로 다른 배열을 받는다.
14. SIZES 의 두 이름 각각에 대해 빈 목록이 아닌 결과가 나온다. SIZES 를 돌면서 잰다 —
    뷰포트 이름이 바뀌면 이 단언이 깨져 알려 준다.

오늘 왜 실패하나

MENUS 와 clickPlan 은 아직 없다. shot-args.mjs 파일 자체는 있으니 import 는 성공하고 두
심볼이 undefined 가 되어 케이스마다 따로 실패한다. --menu 는 지금 두 줄표로 시작하는
미지의 옵션이라 shot-args.mjs:41 에서 null 이 된다. 그래서 1번은 "null 이 아니길 기대"
로, 9~14번은 "undefined 라 호출 불가" 로, 2번은 키 부재로 갈린다. 실패 사유가 한
종류로만 나오면 테스트가 무언가를 구별하지 못한다는 신호다.

손대지 말 것

기존 shot-args.test.ts. navbar.tsx — 메뉴 이동은 별건이고 이미 다른 브랜치에 있다.
MinIO 업로드 경로와 버킷 공개 정책. --owner 와 --port 를 함께 막는 기존 규칙.

어떻게 확인하나

빨강에서 새 파일의 단언이 전부 실패하고 실패 사유가 두 종류 이상으로 갈린다.
초록에서 새 파일이 전부 통과하고 기존 shot-args.test.ts 도 그대로 통과한다. 특히 :10 의
toEqual 이 깨지면 menu 키를 빈 값으로 담은 것이다. 전체 스위트가 초록이어야 한다.
