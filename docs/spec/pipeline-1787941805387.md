**자리 — 새 디렉터리를 만들지 마라**

전부 webapp/src/lib/ **바로 아래** 평평하게 둔다. 하위 디렉터리를 새로 만들면 안 된다.

- webapp/src/lib/eternia-deck-rng.ts — 결정적 난수
- webapp/src/lib/eternia-deck-cards.ts — 카드 데이터
- webapp/src/lib/eternia-deck-combat.ts — 전투 규칙과 상태 전이
- webapp/src/lib/eternia-deck-combat.test.ts — 테스트, 이 파일 하나뿐

타입은 위 세 파일 중 어울리는 곳에 둔다. 타입 전용 파일을 따로 만들지 않는다.

이유는 하네스 쪽 제약이다. 지금 파이프라인은 바뀐 파일을 git status --porcelain 으로
세는데(pipeline.mjs:115), 통째로 새로 생긴 디렉터리는 한 줄로 접혀서 나온다. 실측했다 —
파일 다섯이 든 새 디렉터리가 물음표 두 개에 webapp/src/lib/eternia-deck/ 한 줄이 된다.
그러면 .test.ts 로 끝나는 경로가 하나도 안 보여 테스트를 안 만든 것으로 판정된다.
webapp/src/lib/ 은 이미 추적되는 디렉터리라 그 바로 아래 새 파일은 한 줄씩 제대로 나온다.

접힘 자체를 고치는 브랜치는 따로 있고(pipeline/1787934507729) 머지되면 그때 세 파일을
webapp/src/lib/eternia-deck/ 아래로 옮기면 된다. 이름만 바꾸는 일이라 규칙은 안 건드린다.

**껍데기**

새 모듈이라 테스트가 import 할 대상이 없다. 껍데기를 만든다 — 타입과 시그니처만 두고
본문은 throw new Error('createRun 미구현') 처럼 **함수마다 다른 문구로** 던진다.
문구를 함수마다 다르게 하는 이유는 빨강의 실패 사유가 한 종류로 뭉치지 않게 하기
위해서다. 껍데기에 규칙을 조금이라도 구현하지 마라 — 그건 코더 몫이다.

**말**

화면에 나올 글자는 전부 한글이다. 코드 안쪽 식별자는 영문이고, 한글은 name 값에만
둔다. 그래야 카드를 늘릴 때 데이터만 고치면 된다.

**난수 — eternia-deck-rng.ts**

시드는 회차 시작에 한 번 정해져 회차 내내 산다. 회차 번호에서 파생시키지 않는다
(그러면 3회차가 영원히 같은 3회차가 된다).

상태는 **직렬화 가능한 수 하나**여야 한다. 함수 참조나 클로저를 상태에 담지 마라.

- nextRandom(state) 는 value 와 새 state 를 돌려준다. value 는 0 이상 1 미만.
  같은 state 를 넣으면 늘 같은 것이 나온다.
- shuffle(items, state) 는 섞인 배열과 새 state 를 돌려준다. Fisher-Yates 로 하고,
  입력 배열을 **변형하지 않는다**. 빈 배열과 한 장짜리 배열도 예외 없이 받는다.

**카드 — eternia-deck-cards.ts**

카드 한 장은 id, name, cost, effect 를 가진다. effect 는 함수가 아니라 태그다 —
kind 가 damage 또는 block 이고 amount 가 수다. 함수 참조로 두면 나중에 저장·재생을
붙일 때 직렬화가 막힌다.

여덟 장을 정확히 이 값으로 둔다. 차례로 id, 한글 이름, 비용, 종류, 수치다.

- jab, 찌르기, 0, damage, 3
- strike, 베기, 1, damage, 6
- flurry, 난격, 2, damage, 9
- heavy_strike, 내려치기, 3, damage, 14
- sidestep, 흘리기, 0, block, 2
- guard, 막기, 1, block, 5
- brace, 버티기, 2, block, 9
- iron_wall, 철벽, 3, block, 15

STARTER_DECK 은 이 여덟 장의 id 를 **한 장씩** 담은 목록이다. 여덟 장이라 손패 다섯
장을 두 번 뽑으면 바닥나고, 셋째 턴에 버림 더미를 되돌려야 한다. 그 경계를 일부러 만든
것이니 장수를 바꾸지 마라.

**전투 규칙 — eternia-deck-combat.ts**

한 회차의 상태는 이렇다. 전부 평범한 값이어야 한다 — JSON 을 거쳐 되돌려도 같은 값이어야
한다.

- rngState 는 수
- player 는 hp, block, energy 를 가진다
- enemy 는 hp, moves, moveIndex 를 가진다
- drawPile 은 카드 id 배열. 맨 앞에서 뽑는다
- hand 는 카드 id 배열
- discardPile 은 카드 id 배열
- turn 은 수. 1부터
- outcome 은 ongoing 또는 won 또는 lost 셋 중 하나인 문자열

적 행동은 시드에서 뽑지 않는다. moves 를 순서대로 돌린다 — moveIndex 는 매 턴 다음
칸으로 넘어가고 끝에 닿으면 처음으로 돌아온다. 시드에 묶으면 셔플 시드와 얽혀 테스트가
읽기 어려워진다.

EnemyMove 는 kind 가 attack 이고 amount 가 수인 것 하나뿐이다.

함수 셋:

- createRun(seed, enemy 는 선택) 은 시작 상태를 낸다. 플레이어 hp 50, block 0,
  energy 3. 적 기본값은 hp 40 이고 moves 는 amount 8 짜리 attack 과 amount 12 짜리
  attack 둘. STARTER_DECK 을 시드로 섞어 drawPile 에 넣고 **다섯 장을 뽑아** hand 에
  둔다. turn 은 1, outcome 은 ongoing.
- playCard(state, cardId) 는 새 상태를 낸다.
- endTurn(state) 는 새 상태를 낸다.

**전이 규칙 — 경계까지**

playCard:

- 낼 수 없으면 **상태를 값으로 그대로 돌려준다.** 예외를 던지지 않는다. 낼 수 없는 경우는
  셋이다 — 손패에 그 id 가 없을 때, 기력이 cost 보다 모자랄 때, outcome 이 ongoing 이
  아닐 때
- 낼 수 있으면 기력에서 cost 를 빼고, 손패에서 **그 id 한 장만** 빼서 버림 더미 맨
  뒤에 넣는다. 같은 id 가 손패에 둘이면 하나만 빠진다
- damage 는 적 hp 에서 amount 를 뺀다. 적 방어도는 없다
- block 은 플레이어 방어도에 amount 를 더한다. 상한은 없다
- 적 hp 가 0 이하가 되면 그 자리에서 outcome 이 won 이다. hp 는 음수로 남겨도 된다

endTurn:

- outcome 이 ongoing 이 아니면 상태를 그대로 돌려준다
- 손패를 **전부** 버림 더미 뒤로 보낸다. 손패는 빈다
- 적이 예고한 행동을 실행한다. attack 은 플레이어 방어도가 먼저 흡수한다 — 피해가
  방어도보다 작거나 같으면 hp 는 안 깎이고, 크면 차액만큼 깎인다
- 그 뒤 방어도를 0 으로 만든다. 남은 방어도는 다음 턴으로 안 넘어간다
- 플레이어 hp 가 0 이하가 되면 outcome 이 lost 이고 **거기서 멈춘다** — 다음 턴을
  시작하지 않는다
- 아니면 moveIndex 를 넘기고, turn 을 하나 올리고, 기력을 3 으로 되돌리고, 다섯 장을
  뽑는다

뽑기:

- drawPile 맨 앞에서 뽑는다
- 뽑는 도중 drawPile 이 비면, discardPile 을 시드로 섞어 drawPile 로 옮기고
  discardPile 을 비운 뒤 계속 뽑는다
- 둘 다 비면 **있는 만큼만** 뽑고 끝낸다. 예외를 던지지 않는다

**테스트 — webapp/src/lib/eternia-deck-combat.test.ts**

설명은 한글로 쓰고, describe 블록에 그 함수가 무엇인지 주석을 단다.

반드시 덮을 것:

1. 같은 시드로 createRun 을 두 번 부르면 상태가 완전히 같다. 다른 시드면 drawPile
   순서가 다르다. 서로 다른 시드 둘을 골라 실제로 달라지는 값을 쓴다
2. createRun 직후 손패 5장, drawPile 3장, discardPile 0장. 세 더미를 합치면
   STARTER_DECK 과 같은 여덟 장이다. 순서는 무관하니 정렬해 비교한다
3. 기력이 모자란 카드를 내면 상태가 안 바뀐다. 손패에 없는 id 도 마찬가지
4. block 카드를 낸 뒤 적 공격이 방어도보다 **작을 때** hp 가 안 깎인다
5. 방어도와 피해가 **정확히 같을 때** hp 가 안 깎인다
6. 피해가 방어도보다 클 때 차액만큼만 깎인다
7. 방어도는 턴을 넘기지 않는다 — 막기를 낸 다음 턴 시작 시 block 이 0 이다
8. 세 턴을 돌리면 버림 더미가 섞여 뽑기 더미로 되돌아온다. 카드 여덟 장이 사라지지도
   늘어나지도 않는다. 매 턴 세 더미 합이 늘 여덟 장인지 본다
9. 덱을 통째로 비운 상태를 만들어 뽑을 것이 하나도 없을 때, 예외 없이 손패가 빈 채로
   턴이 넘어간다
10. 적 hp 를 0 이하로 만들면 outcome 이 won 이고, 그 뒤 playCard 와 endTurn 이 상태를
    안 바꾼다
11. 플레이어 hp 가 0 이하가 되면 outcome 이 lost 이고 턴이 안 올라간다
12. 적 행동이 두 개를 번갈아 쓴다 — 1턴 끝에 8, 2턴 끝에 12, 3턴 끝에 다시 8
13. playCard 와 endTurn 이 **입력 상태를 변형하지 않는다.** 부르기 전에 깊은 복사를
    떠 두고 부른 뒤 원본이 그대로인지 본다
14. createRun 이 낸 상태가 JSON 직렬화를 거쳐 되돌려도 같다
15. shuffle 이 입력 배열을 변형하지 않고, 같은 시드면 같은 결과를 낸다. 빈 배열과 한
    장짜리 배열도 예외 없이 받는다

**시드를 고르는 법**

테스트에서 특정 카드를 손에 쥐어야 할 때, 시드를 찍어 맞추려 하지 마라. 상태가 평범한
값이니 손패와 기력을 직접 지어서 넘기면 된다. 그게 경계를 겨냥하는 가장 싼 길이고,
시드 탐색은 구현이 바뀔 때마다 깨진다.

**어떻게 확인하나**

- 빨강 — 열다섯 항목이 전부 실패한다. 실패 사유가 한 종류만 나오면 껍데기 문구를 함수마다
  다르게 두지 않은 것이다
- 초록 — 새 파일이 전부 통과하고 전체 스위트도 그대로 통과한다. 기존 파일을 하나도
  안 고쳤으니 남의 테스트가 깨지면 스펙 범위를 벗어난 것이다

**검수에서 볼 자리**

- import 해 놓고 안 쓰는 것이 없어야 한다. 어젯밤 다른 건에서 순수 함수를 만들어 놓고
  호출부에 안 물린 채 import 만 남긴 일이 있었다(pipeline/1787937993935 의

- 카드 여덟 장의 이름·비용·수치가 위 표와 글자 그대로 같은지 본다
