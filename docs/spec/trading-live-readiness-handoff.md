## 2. 2주 뒤 반드시 확인할 것

### ① VR 사이클 경계가 **2026-10-16 에 처음 발화**한다 (가장 중요)

`#535` 의 가장 큰 변경이고 **운영에서 한 번도 안 돌았다.**
`historyLong → advanceCycleVR → nextCycleAnchor` 왕복이 실제 broker·스케줄러·DB 로 돈 적이 없다.

앵커 산술(재현 확인됨):
```
sinceCycle 2 · cycleDays 10 → cycleCalendarDays(10) = 14
지난달력일 = round((2+1)/10 × 14) = 4
첫 실행일(10-06) − 4 = anchor 2026-10-02
첫 경계 = 2026-10-02 + 14 = 2026-10-16
```

**확인 방법**:
```bash
cd ~/site/webapp && node --env-file=.env.local -e '
import("mongoose").then(async (m) => {
  await m.default.connect(process.env.MONGO_URI);
  const db = m.default.connection.db;
  const p = await db.collection("tradingportfolios").findOne({"config.symbol":"SOXL"});
  console.log("state.vr:", JSON.stringify(p.state?.vr));
  for (const r of await db.collection("tradingruns")
      .find({phase:"main"}).sort({_id:-1}).limit(12).toArray())
    console.log(r.dateKey, r.status, "|", String(r.summary||r.error||"").slice(0,120));
  await m.default.disconnect();
})'
```

**봐야 할 것**
- `state.vr.cycleAnchor` 가 생겼는가? 첫 실행 뒤 `"2026-10-02"`, 경계 뒤 `"2026-10-16"`
- 10-16 런 로그에 `사이클 경계: V→... 다음앵커 2026-10-16` 이 찍혔는가
- `V` 가 갱신됐는가 — 그 값이 **전일 종가** 기준인가(장중가면 `#536 ②` 가 안 먹은 것)
- 경계가 **10-16 이 아닌 날** 터졌으면 앵커 시드가 틀린 것이다

### ② real 에서 LOC 가 **첫 실행**이다

`kis-client.ts` 가 paper 에서 LOC·시장가를 **전부 지정가로 강제**한다:

```ts
const dvsn = this.creds.env === "paper" && ordDvsn !== "00" ? "00" : ordDvsn;
```

즉 **지금까지의 체결 이력 전체가 LOC 가 아니라 지정가**였고, v4·VR 사다리가 기대는
**"종가 체결" 가정은 한 번도 검증된 적이 없다.** real 전환 첫 주에 사람이 직접 대조해야 한다
(체결가가 그날 종가와 맞는가).

같은 모양으로 `usRealizedPnl`·`krRealizedPnl` 도 real 전환이 첫 실행이다(코드는 throw→폴백으로 방어).
