## 업적 시스템 개편 (#333)

업적 18개가 **전부 개수 사다리**였다 — 글 1·10·…·10,000개, 덧글 1·…·1,000개, 좋아요 1개.
결이 하나뿐이라, 많이 쓰는 사람만 보상받고 **무엇을 해 볼지는 알려주지 못한다.**

## 무엇이 문제였나 (실측 2026-08-31)

| 항목 | 값 |
|---|---|
| 글 | 174 (2년간) |
| 덧글 | 98 |
| 웹어드벤처 플레이 | **405** — 업적 0개 |
| 레트로 롬 / 세이브 | 16 / 7 — 업적 0개 |
| 달성한 업적 | 7 / 18 |

- **눈금이 현실과 안 맞는다.** 글 2,500·5,000·10,000 은 이 속도로 수십 년짜리다. 지운다.
- **가장 많이 한 활동에 업적이 없다.** 405번 플레이한 웹어드벤처에 업적이 하나도 없었다.
- **잠긴 업적이 안 보인다.** 달성한 것만 보여주니 목표가 안 생긴다.

## 설계 원칙 (웹 조사 반영)

Stack Overflow 배지 체계와 게임 업적 설계 문헌이 공통으로 말하는 것:

- **등급으로 희소성**을 준다 — 동(쉬움) · 은(꾸준함) · 금(어려움).
- **결을 섞는다** — 개수 말고도 **수집**(세트 완성) · **탐험**(기능 발견) · **시간**(기념일·연속)
  · **숨김**(우연한 발견). 한 결만 있으면 배지가 장식이 된다.
- 배지는 **의미 있는 행동**에 붙을 때만 값어치가 있다. 남발하면 값이 떨어진다.

## 구조 — 수집과 판정을 가른다

지금은 액션마다 함수가 따로였다(`checkAndGrantPostCountAchievements` 등 3개). 업적이 40개로
늘고 트리거가 다양해지면 함수가 계속 늘어난다.

```
lib/achievements/
  definitions.ts  업적 표 (순수 데이터). key·name·description·icon·points·tier·hidden·target
  rules.ts        순수 판정. evaluate(stats) → [{key, unlocked, current, target}]
  stats.ts        DB 를 아는 유일한 곳. collectStats(userEmail) → AchievementStats
  grant.ts        부수효과. evaluateAndGrant(userEmail)
```

**업적 하나가 표의 한 줄**이라 새 업적 추가가 한 줄로 끝나고, 판정이 순수라 DB 없이 테스트된다.

## 소급 부여가 공짜로 따라온다

액션별 부분 검사 대신 **전체 재평가**라, 과거 데이터가 자동으로 반영된다. 프로필을 여는 순간
이미 쌓인 기록(글 174·플레이 405)에 대해 한꺼번에 열린다. 별도 마이그레이션이 필요 없다.

## 숨김 업적은 서버에서 가린다

잠긴 숨김 업적의 이름·설명은 **API 응답 단계에서** `???` 로 바꾼다. 클라이언트에서 가리면
devtools 로 다 보여서 숨김이 아니게 된다.

## 포인트를 코드로 옮긴다

`ACHIEVEMENT_*_POINTS` env 18개가 있었는데 **값이 전부 기본값과 같아** 실질적으로 안 쓰이는
설정이었다. 업적을 40개로 늘리면 env 도 40개가 된다. 포인트를 정의 옆에 직접 적는다 —
바꿀 일이 생기면 코드 한 줄이고, 어차피 env 변경도 재기동이 필요하다.

## 무엇을 지웠나

`POST_COUNT_2500`·`5000`·`10000`. **아무도 달성한 적이 없어**(`achievements` 컬렉션에 7건뿐)
남는 데이터가 없다.

## 소급 예상 (실측 2026-08-31, 안승례 계정)

| 근거 | 값 |
|---|---|
| 글 / 덧글 | 159 / 98 |
| 웹어드벤처 완주 | 405 |
| 본 엔딩 / 굴린 주인공 | **4종 / 2명** (전체는 6종 / 3명) |
| 무결점 완주 | 있음 → 숨김 업적 해금 |
| 롬 / 세이브 | 16 / 7 |
| 최고 좋아요 / 조회 | 4 / 159 |
| 최장 연속 작성 | **6일** (7일에서 하루 모자람) |
| 주말 글 / 새벽 글 | 25 / 35 |
| 가입 경과 | 422일 |

업적 **7개 → 약 22개**로 늘고 **17개가 도전 중**으로 남는다. 중요한 건 **전부 열리지 않는다**는
것이다 — 엔딩 2종·주인공 1명·연속 하루·좋아요 10 처럼 **손이 닿는 다음 목표**가 남는다.
사다리를 현실에 맞게 깎고 결을 섞은 결과다.
