# 파이프라인이 새 디렉터리를 파일로 못 본다 — porcelain 을 -uall 로

## 무엇이 잘못됐나 (실측)

`scripts/ai-team/pipeline.mjs:115` 의 `changedPaths` 가 `git status --porcelain` 을 플래그
없이 부른다. git 은 **통째로 추적되지 않는 디렉터리를 한 줄로 접는다** — 안에 파일이 몇
개든 `?? webapp/src/lib/eternia-deck/` 한 줄이다.

그래서 클로드가 테스트를 **새 디렉터리에** 쓰면 이렇게 된다.

- `changedPaths` 가 디렉터리 경로 하나만 돌려준다
- `isTest('webapp/src/lib/eternia-deck/')` 가 거짓이다 — `snapshot.mjs:13` 이
  `\.test\.(ts|tsx)$` 로만 본다
- `testFiles` 가 빈 배열이 되고 `pipeline.mjs:469` 가 "테스트 파일이 만들어지지 않았습니다"
  로 끝낸다

어젯밤 00:40 실행이 정확히 그렇게 끝났다. 워크트리
`/tmp/ai-pipeline-1787931602742-6y8JFN` 에 `webapp/src/lib/eternia-deck/` 가 통째로
untracked 로 남아 있고 그 안에 `combat.test.ts` 를 포함해 파일 다섯이 실제로 있다.
`git status --short` 로 보면 딱 한 줄이다 — `?? webapp/src/lib/eternia-deck/`.
**테스트는 만들어졌는데 파이프라인이 못 본 것이다.**

#319 로 그 자리가 `die()` 에서 `salvage()` 로 바뀌었지만 **이 버그는 그대로다.** 흔적은
남되 판정이 `NO_TESTS` 로 찍히고, `rescue.mjs:49` 의 풀이가 "스펙이 모호하거나 범위가 너무
넓어 무엇을 시험해야 할지 정하지 못한 경우입니다 — 스펙을 좁혀 다시 요청하세요" 로 나간다.
스펙은 멀쩡했다. 다음 회차 클로드가 그 풀이를 믿고 멀쩡한 스펙을 좁히게 된다 — 못 고치는
정도가 아니라 **엉뚱한 데를 파게 만드는 오진**이다.

## 어디에 두나

순수한 부분은 `scripts/ai-team/snapshot.mjs` 에 더한다. 테스트는
`webapp/src/lib/ai-team/porcelain.test.ts` 새 파일이다.

**이 자리를 고른 것이 중요하다.** `webapp/src/lib/ai-team/` 은 이미 있는 디렉터리라
이번 실행에서는 접힘이 안 일어난다. 새 디렉터리에 두면 고치려는 바로 그 버그에 이번
파이프라인이 걸린다. `snapshot.test.ts:10` 이 `scripts/ai-team/*.mjs` 를 vitest 에서
상대경로로 부르는 관행이니 그대로 따른다.

## 만들 것 넷

### 1. `parsePorcelain(text)` — `snapshot.mjs` 에 새로

`git status --porcelain` 출력 한 덩이를 `{ status, path }[]` 로 나눈다. 지금
`pipeline.mjs:114-124` 안에 인라인으로 박힌 것을 꺼낸 것이고 **동작을 바꾸지 않는다.**

- 앞 두 글자가 status, 세 번째 칸부터가 경로. 양끝 공백은 뗀다
- `R  옛.ts -> 새.ts` 는 화살표 뒤(새 이름)를 경로로 삼는다
- 빈 줄은 버린다
- 디렉터리인지 아닌지는 **여기서 판단하지 않는다** — 온 그대로 낸다

### 2. `directoryEntries(entries)` — 같은 파일에 새로

경로가 `/` 로 끝나는 항목만 골라 돌려준다. git 이 디렉터리를 접었다는 신호다. 판단은
여기 한 곳에만 둔다.

### 3. `STATUS_ARGS` — 같은 파일에 새로

`changedPaths` 가 git 에 넘길 인자를 상수로 꺼낸다.
`['status', '--porcelain', '--untracked-files=all']`.

**이 플래그가 실제 고침이다.** 있으면 git 이 디렉터리를 접지 않고 안의 파일을 하나씩 낸다.
상수로 꺼내는 이유는 네트워크·파일 없이 시험하기 위해서다 — `rescue.mjs:9-12` 가 같은
이유로 판정과 문구를 꺼내 뒀다.

`pipeline.mjs:114-124` 의 `changedPaths` 는 `STATUS_ARGS` 로 부르고 파싱을
`parsePorcelain` 에 맡기도록 고친다. 인라인 파싱은 지운다 — 두 벌로 두면 한쪽만 고쳐지는
날이 온다.

### 4. 그래도 접힌 것이 보이면 판정을 갈라 적는다

`-uall` 을 줬는데도 디렉터리 항목이 오면(git 판올림·설정 차이) 지금처럼 뭉뚱그리면 안
된다. `rescue.mjs` 의 `판정풀이` 에 `COLLAPSED_DIR` 을 더한다. 문구의 요건은 둘이다.

- 새 디렉터리가 한 줄로 접혀 파일이 안 보였다는 것을 적는다
- **"스펙을 좁혀" 라는 말이 들어가면 안 된다.** 그게 오진의 알맹이다

`pipeline.mjs:469` 근방에서 `testFiles` 가 비었을 때, `directoryEntries(afterWrite)` 가
비어 있지 않으면 `verdict` 를 `NO_TESTS` 가 아니라 `COLLAPSED_DIR` 로 싣는다. 비어 있으면
지금처럼 `NO_TESTS` 다. `output` 에는 접힌 디렉터리 경로를 적는다.

## 경계 — 새 파일에 이만큼 적는다

`parsePorcelain`

1. 빈 문자열이면 빈 배열. 줄바꿈만 있어도 빈 배열
2. `?? a.ts` → `{ status: '??', path: 'a.ts' }`
3. ` M webapp/src/x.ts` → status 는 `'M'` (앞 두 글자를 trim 한 값)
4. `R  옛.ts -> 새.ts` → path 는 `'새.ts'`. 화살표 앞은 버린다
5. 줄 사이에 빈 줄이 섞여 있어도 그 줄만 버리고 나머지는 그대로 센다
6. `?? webapp/src/lib/eternia-deck/` → path 가 슬래시로 끝나는 그대로 나온다.
   파싱 단계는 이것을 걸러내지 않는다
7. 경로 안에 공백이 있으면 그대로 둔다(따옴표 해석은 이번 범위 밖 — 지금 동작과 같다)

`directoryEntries`

8. 빈 배열이면 빈 배열
9. `x/` 는 잡고 `x.ts` 는 안 잡는다
10. 접힌 것이 여럿이면 온 순서 그대로 전부 낸다
11. 슬래시가 **가운데** 있는 것(`a/b.ts`)은 안 잡는다. 끝만 본다

`STATUS_ARGS`

12. `--untracked-files=all` 이 들어 있다. 이것이 없으면 버그가 그대로다

판정 — `rescue.mjs` 의 공개 함수로 잰다(`판정풀이` 는 비공개다)

13. `stuckIssueBody({ kind: 'GATE_FAILED', verdict: 'COLLAPSED_DIR', … })` 의 본문에
    디렉터리가 접혔다는 풀이가 들어간다
14. 그 본문에 `'스펙을 좁혀'` 가 **안 들어간다**. `NO_TESTS` 본문에는 들어간다 —
    둘을 같은 테스트에서 나란히 재서 갈라지는 것을 못박는다
15. `stuckComment` 도 같은 판정에 같은 풀이를 싣는다

## 오늘 왜 전부 실패하나

`parsePorcelain`·`directoryEntries`·`STATUS_ARGS` 는 오늘 `snapshot.mjs` 에 없다 —
import 는 되지만 값이 `undefined` 라 부르는 순간 터진다. `COLLAPSED_DIR` 은 `판정풀이` 에
없어 `'판정을 확인하세요.'` 가 나오므로 13·15 가 실패하고, 14 는 `NO_TESTS` 쪽 절반만
맞아 실패한다. **실패 사유가 두 종류 이상 나온다** — 한 종류만 나오면 테스트가 아무것도
구별하지 못한다는 신호다.
