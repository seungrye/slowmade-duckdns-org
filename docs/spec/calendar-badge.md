## 헤더 달력 배지 (#328)

오늘이 **공휴일·기념일·24절기**면 헤더에 아이콘을 띄우고, 올리거나 누르면 무슨 날인지 툴팁으로
설명한다. 종류마다 아이콘이 달라 한눈에 구분된다.

## 왜 API 인가 — 하드코딩이 안 되는 이유

설날·추석·부처님오신날은 음력이라 양력 날짜가 매년 바뀌고, 대체공휴일 규칙도 해마다 결과가
다르다. 코드에 표로 박으면 **매년 연말에 손으로 갱신해야 하고, 잊으면 조용히 틀린다**.
공공데이터포털의 한국천문연구원 특일 정보 API 를 쓰면 그 부채가 없다.

## 키가 없으면 조용히 꺼진다

`HOLIDAY_API_KEY` 가 비면 API 가 항상 빈 배열을 주고 배지는 렌더되지 않는다 — 오류도 안 띄운다.
덕분에 키 없이도 기능을 통째로 만들어 머지할 수 있고, 키를 넣는 순간 켜진다.

## 캐시 — 스케줄러 없이

연 단위로 DB(`HolidayCache`)에 통째 저장한다. 주기 작업을 새로 만들지 않고, **필요할 때 캐시가
없으면 그 자리에서 받아 채운다**(자가 치유). 재시작·배포에 영향받지 않는다.

`fetchedAt` 이 **7일**보다 오래면 다시 받는다. 연 1회로는 부족한데, **임시공휴일은 연중에
새로 지정**되기 때문이다. 주 1회면 52회/년이라 유량 걱정이 없다.

수집이 실패하면 **묵은 캐시를 그대로 쓴다** — 달력 때문에 헤더가 깨지면 안 된다.

## 응답 형식을 방어적으로 읽는 이유

이 구현 시점에 서비스 키가 없어 **실제 응답을 확인하지 못했다.** 그래서 파싱을 `parse.ts` 한
곳으로 격리하고, 흔한 변형을 모두 받는다:

- 항목이 1건이면 `items.item` 이 배열이 아니라 **객체**로 온다
- 0건이면 `items` 가 **빈 문자열**일 수 있다
- `locdate` 는 `20260101` 같은 **숫자**다

형식이 다르면 이 파일만 고치면 된다.

## 시각적 무게를 3단으로 나누는 이유

24절기까지 표시하면 공휴일 15일 + 기념일 + 절기 24일로 **연 80일 넘게** 뜬다. 4~5일에 한 번씩
같은 무게로 뜨면 특별한 날이 아니라 장식이 된다. 그래서

- `holiday` 색 배지 (눈에 띔)
- `anniversary` 기본
- `season` 회색·작게 (은은함)

로 나눈다. 아이콘 구분은 *무슨 날인지*를 알려주고, 무게 구분은 *얼마나 중요한지*를 알려준다.

## 설명 문구는 우리가 쓴다

API 는 이름만 준다(`'설날'`). "음력 새해 첫날. 차례를 지내고 세배를 합니다" 같은 문구가 이
기능의 알맹이라, `catalog.ts` 에 이름→{아이콘, 설명} 표를 둔다. **표에 없는 이름도 반드시
보여준다** — 종류별 기본 아이콘 + 이름만. 표에 없다고 안 뜨면 API 가 새 기념일을 줄 때 조용히 샌다.

## 접근성

hover 만으로는 **모바일에서 열 수 없다**. 배지를 `<button>` 으로 만들어 hover·tap·keyboard
focus 모두에서 열고, `Esc`·바깥 클릭으로 닫는다. 로그인 없이도 보인다(공개 데이터).

## 실측으로 드러난 것 (2026-08-31, 키 발급 후)

키를 받아 실제 응답을 확인했다. 형식은 파서가 가정한 것과 같았고(`response.header.resultCode`,
`body.items.item[]`, `locdate` 숫자), 두 가지가 새로 드러났다.

**① `isHoliday` 는 공휴일 엔드포인트에서만 뜻이 있다.** 기념일·24절기 응답은 **모든 항목이
`isHoliday: "N"`** 이다. 그래서 "N 이면 기념일로 낮춘다"를 무조건 적용하면 **24절기가 통째로
기념일로 분류돼** 시각적 무게 3단이 무너진다. 이 규칙은 `getRestDeInfo`(공휴일)에만 적용한다.

덧붙여, `getRestDeInfo` 의 2026년 22건은 **전부 `Y`** 였다 — 제헌절도 포함이다. "제헌절은
국경일이지만 쉬지 않는다"는 옛 상식이라 **코드가 단정하면 안 된다.** 지정은 해마다 바뀌므로
낮추는 분기는 안전망으로만 남긴다.

**② 2026년 기준 건수**: 공휴일 22 · 기념일 82 · 절기 24 = **연 128건**. 기념일이 82건이라
사흘에 한 번꼴로 뭔가 뜬다. `numOfRows` 를 100 으로 두면 기념일이 늘었을 때 조용히 잘리므로
넉넉히 300 으로 올린다.

**③ 엔드포인트마다 띄어쓰기가 다르다.** 기념일은 `'어버이 날'`·`'스승의 날'`·`'국군의 날'`
처럼 띄어 쓰고 공휴일은 붙여 쓴다. 같은 날을 다르게 부르기도 한다(`'노동절'` = `'근로자의 날'`).
대체공휴일은 `'대체공휴일(개천절)'` 처럼 괄호가 붙는다. 표를 두 벌 두지 않고 **찾을 때 공백을
지우고, 괄호가 붙는 이름은 앞부분으로 찾되 표시 이름은 원문을 살린다** — 어느 공휴일의
대체인지가 정보이기 때문이다.

이 대조로 공휴일 18/18 · 절기 24/24 가 표에 걸린다. 기념일은 82종 중 18종만 걸리는데,
나머지(`'조달의 날'`·`'곤충의 날'` 같은 것)는 설계대로 종류별 기본 아이콘 + 이름만 뜬다.

**픽스처로 고정한다.** 실제 응답에서 대표 항목을 추려 `lib/calendar/__fixtures__/live-2026.json`
에 박고 `live-shape.test.ts` 가 종단 확인한다. 목이 아니라 진짜 응답이라, 파서를 건드릴 때
같은 실수를 되풀이하면 거기서 걸린다.

## 겹치는 날 — 아바타 스택 (2026-08-31 변경)

처음엔 아이콘을 나란히 최대 3개 그렸는데, 날마다 헤더 폭이 달라지고 좁은 화면에서 과했다.
프로필 사진 묶음처럼 **겹쳐 쌓는다**.

- 겹치되(`-ml-2`) 링으로 경계를 그어 이모지끼리 뭉개지지 않게 한다. 링 색은 navbar 배경과
  같아야 오려낸 것처럼 보인다.
- 겹쳐 쌓으면 크기로 무게를 나눌 수 없다 — 뒤엣것이 가려진다. 대신 **색**으로 나눈다:
  공휴일 붉게(쉬는 날) · 기념일 푸르게 · 절기 무채색.
- **데스크톱**: 마우스를 올린 칸이 맨 앞으로 나오고(z-index + 강조 링), 툴팁엔 **그 날만**
  설명한다. 키보드 포커스도 같게 동작한다.
- **모바일**: hover 가 없으므로 **누르면 그날 것을 전부** 한 번에 보여준다. 데스크톱에서
  눌러도 같다.
- 3개를 넘으면 마지막 칸이 `+N` 이 되고, 눌러서 전부 읽는다.

## 설명 있는 것만 띄운다

기념일이 연 82종이라(`조달의 날`·`곤충의 날` …) 전부 띄우면 사흘에 한 번꼴로 뭔가 떠서 특별한
날이 아니라 장식이 된다. **설명을 붙일 만큼 알려진 날만** 남긴다.

⚠ 대가: 표에 없는 이름은 **공휴일이라도 안 뜬다.** 그래서 `임시공휴일` 처럼 올 법한 이름을 미리
표에 넣어 뒀다. 새 이름이 보이면 표에 추가할 것.

## 같은 날이 두 번 오는 것

실측: `어린이날`(5/5)·`현충일`(6/6)이 **공휴일과 기념일 응답 양쪽에** 있다. 안 합치면 배지에
두 번 뜬다. 이름으로 합치고 무게가 높은 쪽(공휴일 > 기념일 > 절기)을 남긴다. 정렬도 무게순이라
**스택 맨 앞이 늘 그날의 가장 중요한 날**이다.
