# 파이프라인을 클로드가 띄우지 않는다 — 러너가 전경으로 돌린다

관련: #292

## 왜

야간 파이프라인이 매일 밤 SIGKILL 로 죽고 있었다. 클로드가 직접 띄우는데
(`run.sh` 허용 목록의 `Bash($PIPELINE *)`) 파이프라인은 20분~3시간짜리라 `Bash` 도구
타임아웃을 넘긴다. 그래서 클로드가 백그라운드로 돌리고 "완료 알림을 기다리겠습니다" 하고
턴을 끝낸다 → `claude -p` 종료 → `Type=oneshot` cgroup 정리로 SIGKILL.

SIGKILL 이라 `salvage()` 도 안 돈다. 8/28 실행은 **빨강 게이트까지 통과**하고 코더가 구현
중이었는데 브랜치도 이슈도 덧글도 안 남았다.

`TimeoutStartSec` 3시간(#289)이 효과가 없었던 이유가 이것이다 — 30분에 잘린 게 아니라
클로드가 먼저 손을 놓았다.

## 무엇을 바꾸나

### 1. 클로드는 **요청만** 남긴다

허용 목록에서 `Bash($PIPELINE *)` 를 뺀다. 대신 스펙을 `/tmp/spec-*.md` 에 쓰고
요청 파일 `/tmp/spec-pipeline-request` 를 남긴다. 기존 `Bash(cat > /tmp/spec-*)` ·
`Bash(tee /tmp/spec-*)` 허용이 그대로 덮으므로 새 권한이 늘지 않는다.

```
spec=/tmp/spec-red-kinds.md
post=6a8bf1c452e0ccc4611ca2ae
```

### 2. `run.sh` 가 `claude -p` **뒤에** 전경으로 돌린다

`ExecStart` 안에서 도니 cgroup 정리에 안 걸리고 `TimeoutStartSec` 3시간이 실제로 걸린다.
클로드가 비정상 종료해도 요청 파일이 있으면 돌린다 — 스펙까지 써 놓고 죽은 것을 버릴
이유가 없다.

### 3. 성공도 스레드에 알린다

클로드는 이제 결과를 못 본다(먼저 끝난다). 지금은 막혔을 때(`salvage`)만 알리므로,
**초록으로 끝났을 때도 `--post` 스레드에 브랜치를 남긴다.**

## 만들 것

| 파일 | 하는 일 |
|---|---|
| `scripts/ai-team/request.mjs` | `REQUEST_PATH` · `parseRequest(text)` — 순수 파서 |
| `scripts/ai-team/run-pipeline.mjs` | 요청을 읽어 검증하고 `pipeline.mjs` 를 전경 실행 |

`parseRequest` 는 파일을 읽지 않는다 — 문자열만 받는다. 그래야 파일 없이 시험한다.

## 수용 기준

- `spec=` 없으면 `null` — 요청으로 안 본다
- `spec` 은 `/tmp/spec-` 으로 시작하는 절대경로만 받는다. 저장소 경로·상대경로·다른 디렉터리는 거절
- `post` 는 없어도 되고, 있으면 24자리 16진수만 받는다
- 빈 줄·`#` 주석·모르는 키는 건너뛴다
- 값의 앞뒤 공백은 턴다. `=` 가 값에 들어 있어도 첫 `=` 로만 가른다
- 위 전부 파일·네트워크 없이 도는 vitest 로 덮는다
