**무엇을 만드나 — 캡처가 메뉴를 펼친 뒤 찍게 한다**

`shot.mjs` 는 `page.goto` 직후 바로 찍어서 **접힌 네비바**만 나온다. 네비바 드롭다운은
hover 가 아니라 클릭으로 열린다(`navbar.tsx:232`, `:395`, `:426`). 그래서 사람이 요청한
"게임 메뉴 안의 서버 상태" 는 지금 도구로는 화면에 아예 안 담긴다.

`--menu <논리이름>` 을 받아 **뷰포트별로 눌러야 할 aria-label 순서**로 번역하고, 그 순서대로
눌러 펼친 뒤 찍는다.

순수 규칙은 `scripts/ai-team/shot-args.mjs` 에 두고 `webapp/src/lib/ai-team/shot-menu.test.ts`
로 덮는다. 브라우저를 모는 얇은 부분만 `shot.mjs` 에 둔다.

**어제 같은 자리에서 멈췄다 — 그 원인부터**

`pipeline/1787953179465` 가 빨강 게이트에서 UNEXPECTED_PASS 로 거부됐다. 원인 둘이다.

첫째, 껍데기가 `export function clickPlan(menu, sizeName) {}` 였다. 빈 몸은 `undefined` 를
내므로 `expect(() => clickPlan('주식','desktop')).not.toThrow()` 가 **구현 없이 통과**한다.

둘째, 지금의 `parseShotArgs` 는 `--menu` 를 모르는 옵션으로 보고 `a.startsWith('--')` 에서
`null` 을 낸다(`shot-args.mjs:41`). 그래서 "값이 없으면 거절" "두 번 주면 거절" "모르는
이름은 거절" 같은 **거절 단언이 전부 오늘도 통과**한다.

이번 스펙은 그 둘을 못박는다.

**내보낼 것 — MENUS**

논리 이름에서 뷰포트별 라벨 순서로 가는 표. 얼려서 낸다.

| 논리 이름 | desktop | mobile |
|---|---|---|
| `게임` | `게임 메뉴` | `모바일 메뉴 열기` → `모바일 게임 섹션 토글` |
| `에테르니아` | `게임 메뉴` → `에테르니아의 추락 하위 메뉴` | `모바일 메뉴 열기` → `모바일 게임 섹션 토글` → `모바일 에테르니아의 추락 토글` |

라벨은 마크업에 이미 있는 `aria-label` 그대로다 — `navbar.tsx:233`, `:263`, `:395`,
`:426`, `:463`. 새로 붙일 것이 없다.

두 항목을 다 두는 이유: 서버 상태는 지금 **에테르니아 하위**에 있고(`navbar.tsx:79`),
메뉴 이동 브랜치가 배포되면 **게임 바로 아래**로 온다. 두 자리를 다 찍을 수 있어야
"고치기 전" 과 "고친 뒤" 를 같은 도구로 낼 수 있다.

**내보낼 것 — clickPlan(menu, sizeName)**

그 뷰포트에서 메뉴를 펼치려면 무엇을 어떤 순서로 누르는지 낸다.

| 입력 | 결과 |
|---|---|
| `('게임','desktop')` | `['게임 메뉴']` |
| `('게임','mobile')` | `['모바일 메뉴 열기','모바일 게임 섹션 토글']` |
| `('에테르니아','desktop')` | `['게임 메뉴','에테르니아의 추락 하위 메뉴']` |
| `('에테르니아','mobile')` | 위 모바일 둘 뒤에 `모바일 에테르니아의 추락 토글` |
| `(undefined, 아무거나)` | `[]` — 메뉴를 안 줬으면 모바일이라도 햄버거를 자동으로 열지 않는다 |
| `('주식','desktop')` | `[]` — 모르는 이름. **던지지 않는다** |
| `('게임','태블릿')` | `[]` — 없는 뷰포트 |

**매번 새 배열**을 낸다. 부르는 쪽이 고쳐 써도 `MENUS` 가 안 바뀌어야 한다.

**parseShotArgs 에 --menu 더하기**

| 인자 | 결과 |
|---|---|
| `['/games','--menu','게임']` | `{path:'/games', owner:false, port:0, menu:'게임'}` |
| `['/games','--menu']` | `null` — 값이 없다 |
| `['/games','--menu','--owner']` | `null` — 다음 인자를 삼키면 `--owner` 가 조용히 사라진다 |
| `['/games','--menu','주식']` | `null` — `MENUS` 에 없는 이름 |
| `['/games','--menu','게임 ']` | `null` — 공백이 붙은 이름도 거절. 다듬지 않는다 |
| `['/games','--menu','게임','--menu','게임']` | `null` — 두 번 |
| `['/','--menu','게임','--owner']` | `{path:'/', owner:true, port:0, menu:'게임'}` |
| `['/','--owner','--menu','게임']` | 위와 같다 — 순서 무관 |
| `['/games','--menu','게임','--port','3011']` | `{path:'/games', owner:false, port:3011, menu:'게임'}` |
| `['/games']` | **`menu` 키가 아예 없다** |

마지막 줄이 중요하다. 기존 `shot-args.test.ts:11` 이 세 키로 `toEqual` 을 재고 있다.
빈 값으로라도 `menu` 를 담으면 그 단언이 깨진다.

`--owner` 와 `--port` 를 함께 못 쓰는 기존 제약(`shot-args.mjs:53`)은 그대로다. `--menu`
는 어느 쪽과도 함께 쓸 수 있다.

**껍데기는 반드시 throw 한다**

`clickPlan` 은 빈 몸이 아니라 `throw new Error('아직')` 로 둔다. 빈 몸이면 위에 적은
`not.toThrow()` 단언이 구현 없이 통과해 빨강 게이트가 즉사한다.

`MENUS` 는 껍데기 단계에서 `Object.freeze({})` 로 둔다 — 테스트가 `MENUS['게임'].mobile`
에 닿아 TypeError 로 실패한다. 이것이 `clickPlan` 의 throw 와 **다른 종류의 실패**라,
빨강 실패 사유가 두 종류 이상 섞인다.

**테스트를 쓸 때 지킬 것**

거절만 재는 `it()` 을 만들지 말 것. 위에 적은 대로 거절 단언은 오늘도 전부 통과한다.
거절 단언은 **받아들이는 단언과 같은 `it()` 안에 묶는다** — 그러면 그 블록이 오늘
실패한다. 예를 들어 "값이 없으면 거절" 과 "아는 이름이면 받는다" 를 한 블록에 넣는다.

같은 이유로 "`--menu` 를 안 주면 `menu` 키가 없다" 도 단독으로 두면 오늘 통과한다.
"안 주면 없고, 주면 있다" 를 한 블록에 넣는다.

**shot.mjs 쪽 — 테스트 밖이다**

- `SIZES` 를 도는 고리 안, `page.goto` 뒤 `page.screenshot` 앞에서
  `clickPlan(opts.menu, size.name)` 을 받아 그 순서대로 `page.getByLabel(라벨).click()` 한다.
- 라벨을 못 찾으면 `die()` 로 멈춘다. 조용히 접힌 화면을 찍어 올리면 사람이 잘못된 것을
  보고 판단한다 — 세션 가드(`shot.mjs:95`)와 같은 까닭이다.
- 한 번 누를 때마다 짧게 기다린다(펼침이 그려질 시간). 300ms 면 된다.
- 사용법 문구(`shot.mjs:32`)에 `[--menu <이름>]` 을 더한다.
