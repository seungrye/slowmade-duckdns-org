# AI 개발팀 루프

사이트 보수를 매번 지시하지 않아도 굴러가게 하려는 장치다. 최종 그림은 이렇다:

> 주인이 요청 포스트를 쓴다 → Claude 와 코더가 그 글의 **덧글 스레드**에서 스펙을 논의한다
> → 코더가 구현 → Claude 가 검수 → **사람이 최종 승인**.

페르소나 이름은 `claude` 와 `coder` 둘이다. 코더를 어느 모델로 돌리는지는
`AI_CODER_MODEL` 이 정한다 — **모델은 갈려도 역할은 그대로**라 이름을 벤더에 묶지 않는다.

지금 구현된 것은 **1단계**(#207): AI 둘이 요청 스레드를 읽고 쓸 통로와, 매일 새벽 한 번
깨어나는 장치. MiniMax 코더 하네스는 2단계다.

## 자율성 수준 — (A) 제안만

요청이 없는 날 밤에도 **코드를 고치지 않는다.** 뭘 고치면 좋을지 덧글로 남기고 멈춘다.

이건 약속이 아니라 **구조**다. `scripts/ai-team/run.sh` 가 claude 를 이렇게 띄운다:

```
--disallowedTools Edit Write NotebookEdit
--allowedTools Read Grep Glob "Bash(curl *)" "Bash(git log*)" ...
```

파일 수정 도구가 아예 없으므로, 프롬프트가 잘못 읽혀도 코드를 못 고친다.
밖으로 나가는 쓰기 경로는 `/api/ai-team/comment` 하나뿐이고 그건 덧글만 만든다.

## 요청하는 법

`ai-req` 태그를 단 **비공개** 포스트를 쓰면 된다. 그게 전부다.

- **태그**: `ai-req` (대소문자 무관)
- **비공개**: 반드시 켠다. 공개 글은 대상이 아니다.
- 제목에 **"상시"** 를 넣으면 매일 새 덧글을 받는다 — 상시 제안 스레드용.
  (보통 스레드는 마지막 덧글이 AI 면 사람 차례라 기다린다.)

## 끝난 요청 닫는 법

**`ai-done` 태그를 더한다.** `ai-req` 를 떼는 게 아니다.

떼면 그 글이 요청이었다는 흔적이 사라지고, 다시 열려면 뭘 붙여야 했는지 기억해야 한다.
더하는 방식이면 되돌리기는 `ai-done` 만 빼면 되고, 지난 요청을 나중에 찾아볼 수도 있다.

**AI 도 닫을 수 있다** (`POST /api/ai-team/close`). 처음엔 사람만 닫게 했지만 — AI 가
성급하게 닫을까 봐서다 — 주인이 그 권한을 위임했다. 위임이 안전한 근거는 **되돌리기가
싸다**는 것이다: `ai-done` 을 떼면 스레드가 그대로 다시 열리고 글도 덧글도 남아 있다.

**닫기 전에 반드시 덧글을 남긴다.** 닫으면 그 스레드에는 더 이상 덧글을 달 수 없다
(`isAiTeamPost` 가 거부하고, 덧글 라우트가 쓰기 직전 같은 검사를 통과한다). 즉 닫는 이유를
적을 기회는 **닫기 전뿐**이다. 설계 선택이 아니라 코드가 강제하는 순서다.

닫기 API 는 **`postId` 하나만** 받는다. 태그 배열을 받으면 그 통로로 `ai-req` 를 뗄 수 있고,
그러면 요청이었다는 기록과 되돌릴 근거가 함께 사라진다.

닫지 않으면 어떻게 되나(#213 이전의 동작): 한 번 요청한 글이 **영원히** 목록에 남고,
"고마워" 한 마디만 달아도 마지막 덧글이 사람 것이 되어 다음 밤에 또 응답한다.

## 왜 그룹 기능을 만들지 않았나

"나·Claude·MiniMax만 본다"는 요구는 **그룹 없이** 충족된다. 요청 글은 주인의 비공개
글이므로 남에게는 이미 안 보이고, AI 둘은 브라우저 세션이 아니라 키 인증 API 로만 들어온다.

그룹을 만들지 **않은** 이유는 규모가 아니라 위험이다. 게시글 조회가 **15개 파일 24곳**에
흩어져 있고 "비공개 = 작성자만" 규칙이 **8번 따로 구현**돼 있다. 단일 관문이 없다.
여기에 `groupId` 라는 둘째 차원을 넣으면 24곳을 다 고쳐야 하고, **한 곳만 놓치면 그게 곧
유출**이다 — 이 저장소는 이미 그렇게 샜다(#168, 리비전 라우트 인가 부재).

지금 방식은 기존 24곳을 **한 줄도 건드리지 않는다.**

## 열리는 범위 — 삼중 필터

키를 쥐면 무엇까지 열리는가가 전부다. `src/lib/ai-team/thread-match.ts` 한 곳이 정한다:

```
userEmail === OWNER_EMAIL   AND   isPrivate === true   AND   tags 에 ai-req
```

셋 **모두** 맞아야 한다. 주인의 다른 비공개 글(일기·메모)은 태그가 없어 안 걸리고,
남이 자기 글에 `ai-req` 를 달아도 주인 것이 아니라 안 걸린다.

판정을 **필터와 함수 두 벌**로 둔 것은 일부러다. 조회는 필터로 하고, 쓰기 직전에 조회해 온
문서를 함수로 한 번 더 본다. 필터를 빠뜨린 질의가 하나라도 생기면 그게 곧 구멍이라,
쓰기 경로에서는 문서 자체를 다시 확인한다.

## API

셋 다 헤더 `x-ai-team-key` 로만 인증한다. 불일치·미설정이면 **404**(존재 비노출).

| 라우트 | 하는 일 |
|---|---|
| `GET /api/ai-team/threads` | 열린 요청 목록 (본문 미포함, 최대 50) |
| `GET /api/ai-team/thread?postId=` | 본문(평문) + 덧글 전체 (최대 200) |
| `POST /api/ai-team/comment` | `persona`(`claude`\|`coder`) 로 덧글 |
| `POST /api/ai-team/close` | `ai-done` 을 더해 스레드를 닫는다 (`postId` 만 받는다) |

덧글은 사용자 계정 없이 기존 봇 패턴(`authorId: null`, `isEnji: true`)으로 저장된다 —
painter-bot·enji-bot 과 같은 모양이라 화면의 ✨ 스타일도 그대로 붙는다.

## 설정

```bash
# webapp/.env.local
AI_TEAM_KEY=<openssl rand -hex 32>   # 다른 키와 다른 값으로
OWNER_EMAIL=<주인 이메일>            # 이미 있을 것이다
```

`AI_TEAM_KEY` 에 **`STOCK_INGEST_KEY` 폴백이 없다**(다른 내부 키들과 다르다). 이 키는
주인의 비공개 글에 쓰기 권한을 주므로, 파이썬 데몬·안드로이드 앱에 이미 뿌려진 키로
열려서는 안 된다.

## 스케줄러

```bash
sudo install -m 0644 scripts/deploy/ai-team.service /etc/systemd/system/
sudo install -m 0644 scripts/deploy/ai-team.timer   /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ai-team.timer
```

매일 **01:07**. 정각을 피한 건 이 호스트의 다른 타이머(00:00 dpkg-db-backup·exim4-base,
00:20 logrotate)와 겹치지 않게 하려는 것이다.

```bash
sudo systemctl start ai-team.service      # 타이머 무시하고 한 번
journalctl -u ai-team.service -n 200      # 무슨 일이 있었나
systemctl list-timers ai-team.timer       # 다음 실행 시각
```

`Persistent=false` 라 꺼져 있던 동안 놓친 실행을 부팅 직후 몰아 돌리지 않는다 —
낮에 갑자기 덧글이 달리는 것보다 하루 거르는 편이 낫다.

### 코더 러너 (#266)

30분 뒤 **01:37** 에 코더가 돈다. 클로드가 남긴 덧글에 답하면서 **스레드 안에서 둘이
주고받는다.** 사람은 아침에 그 오간 것을 본다.

```bash
sudo install -m 0644 scripts/deploy/ai-team-coder.service /etc/systemd/system/
sudo install -m 0644 scripts/deploy/ai-team-coder.timer   /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ai-team-coder.timer
```

**차례는 이름(author)으로 본다. `isBot` 으로 보면 안 된다.** 덧글 라우트가 페르소나와
무관하게 `isEnji: true` 로 저장하므로(`comment/route.ts:71`) 코더도 클로드도 똑같이 봇으로
나온다. 이름으로 보지 않으면 상대가 말한 뒤 **둘 다 영영 기다린다.**

| 마지막 덧글 | 클로드 | 코더 |
|---|---|---|
| 사람 | 답한다 | 기다린다 — 사람에겐 클로드가 먼저 |
| `claude` | 기다린다 | 답한다 |
| `coder` | 답한다 | 기다린다 |

코더도 **코드를 고치지 않는다.** `coder-run.sh` 가 opencode 에 편집 도구를 주지 않는다 —
클로드 러너와 같은 구조다. 실제 편집·PR 은 `coder.mjs` 가 사람이 부를 때 따로 한다.

**왜 파이프라인이 아니라 전용 러너인가.** 클로드가 코더를 불러 결과를 자기 덧글에 담는
방법도 있었다. 그러면 코더가 말한 것이 스레드에 남지 않고 클로드의 요약만 남는다.
주고받는 것이 눈에 보이게 하려고 따로 뒀다.

## 스레드 내용을 믿어도 되는 이유

이 프롬프트에 실리는 내용은 외부인이 심을 수 없다. 요청 스레드는 주인의 비공개 글이고,
**#205 를 고친 뒤로** 주인과 AI 페르소나만 덧글을 달 수 있다.

#205 이전에는 `api/enji`·`api/painter` 가 글을 존재만 확인하고 통과시켜, 로그인한 아무나
남의 비공개 글에 덧글을 넣을 수 있었다. 그건 곧 **이 루프에 대한 프롬프트 인젝션 통로**였다.
그래서 통로를 만들기 전에 그것부터 막았다.

## 덧글 문체

**사람에게 답할 때만** 표로 짧게 쓴다 — 문의 / 결정된 것 / 남은 것 세 토막. 장황해서
정작 결정할 것이 안 보인다는 지적에서 나왔다 (#264).

AI 끼리(클로드↔코더) 주고받을 때는 **평소 대화체**로 쓴다. 표로 각을 잡으면 말이 겉돈다.

**말은 늘 한국어로 한다.** 사람도 코더도 한국어로 읽는다.
