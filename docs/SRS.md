# Software Requirements Specification (SRS)

## 1. 소개

### 1.1 목적

Handmade Site는 사용자들이 유머 게시글을 작성, 공유, 조회, 태깅, 댓글 및 좋아요 기능을 통해 소통할 수 있는 웹 애플리케이션입니다.

### 1.2 범위

이 문서는 프로젝트의 기능 요구사항과 비기능 요구사항을 정의합니다.

### 1.3 용어 정의

- 사용자(User): 사이트를 이용하는 일반 방문자 또는 로그인 사용자
- 게시글(Post): 제목, 본문, 태그, 이미지, 작성자 정보를 포함하는 글
- 태그(Tag): 게시글 분류 및 검색을 위한 키워드
- 댓글(Comment): 게시글에 대한 사용자 의견
- 좋아요(Like): 게시글에 대한 사용자 반응
- 인증(Authentication): `next-auth` 기반 로그인

## 2. 전반적 설명

### 2.1 제품 관점

웹 애플리케이션은 프론트엔드 Next.js `app` 디렉터리 기반 라우팅과 백엔드 API 경로(`app/api/*`)로 구성됩니다.

### 2.2 사용자 유형

- 비회원: 게시글 목록 조회, 태그 검색, 게시글 상세 페이지 접근
- 회원: 게시글 작성, 수정, 삭제, 댓글 작성, 좋아요/싫어요, 내 업로드 보기, 내 설정 관리
- 관리자(잠재): 사용자 인증 정보가 있는 경우 추가 권한 관리 가능

## 3. 기능 요구사항

### 3.1 인증

- `next-auth`를 이용한 로그인/로그아웃
- 로그인된 사용자만 게시글 쓰기, 수정, 삭제, 댓글 작성, 좋아요/싫어요 수행

### 3.2 게시글 관리

- 게시글 목록 조회
- 게시글 상세 보기
- 게시글 작성 및 수정
- 게시글 업로드 이미지 첨부
- 게시글 태그 추가 및 편집

### 3.3 태그 기능

- 태그 클라우드 또는 태그 목록 페이지 제공
- 태그 클릭 시 해당 태그가 포함된 게시글 목록 표시

### 3.4 댓글 기능

- 게시글에 댓글 추가
- 댓글 목록 조회
- 댓글 삭제 또는 수정(구현 여부에 따라 확장)

### 3.5 좋아요/싫어요

- 게시글에 대한 좋아요/싫어요 기능
- 해당 상태를 사용자별로 관리

### 3.6 대시보드

- 사용자가 본인이 작성한 게시글 목록 보기
- 사용자가 작성한 댓글 관리
- 프로필 및 설정 페이지 접근

### 3.7 에디터

- `tiptap` 기반 리치 텍스트 에디터 제공
- 이미지 업로드, 제목 입력, 본문 작성
- 작성 중 자동 저장 기능은 선택 사항(현재는 명시적 저장)

## 4. 비기능 요구사항

### 4.1 성능

- 목록 페이지는 페이징 또는 무한 스크롤을 통해 초기 로딩 비용을 낮춰야 함
- 이미지 업로드 처리 시 비동기적 처리가 가능해야 함

### 4.2 보안

- 인증된 사용자만 민감 정보에 접근하도록 제한
- 서버 측 요청 검증 및 입력값 필터링 필요
- 파일 업로드 허용 형식과 크기 제한 필요

### 4.3 유지보수성

- 컴포넌트 기반 재사용성과 명확한 디렉터리 구조 유지
- API 경로는 기능별로 분리(`post`, `posts`, `comments`, `tags`, `user` 등)

### 4.4 접근성

- 버튼 및 폼 입력에 대한 적절한 aria 속성 제공
- 키보드 네비게이션 및 화면 읽기 도구 호환성 검토

## 5. 주요 사용자 시나리오

### 5.1 게시글 탐색

1. 사용자는 홈 페이지 진입
2. 최신 게시글 목록을 확인
3. 게시글을 클릭하여 상세 내용 보기

### 5.2 태그별 검색

1. 사용자는 태그 페이지 진입
2. 검색한 태그를 클릭
3. 해당 태그가 포함된 게시글 목록 확인

### 5.3 게시글 작성

1. 사용자는 로그인
2. 게시글 작성 페이지 진입
3. 제목/본문/태그 입력
4. 이미지 업로드 및 저장
5. 게시글 제출 후 목록 또는 상세 페이지로 이동

### 5.4 댓글 작성

1. 사용자는 게시글 상세 페이지에서 댓글 입력
2. 댓글 제출 후 목록에 반영

### 5.5 좋아요/조회

1. 사용자는 게시글에서 좋아요 버튼 클릭
2. 좋아요 수가 즉시 반영
3. 조회수는 게시글 조회 시 증가

## 6. 제약 조건

- Next.js `app` 라우터를 사용하여 SSR/SSG 및 클라이언트 컴포넌트를 혼용함
- 데이터 저장소는 MongoDB(Mongoose) 기반
- 이미지 업로드를 위해 `MinIO` 또는 유사 S3 호환 저장소 사용
- 인증은 `next-auth`로 처리
