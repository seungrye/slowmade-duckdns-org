# Software Requirements Specification (SRS)

## 1. 소개

### 1.1 목적

Handmade Site는 사용자들이 유머 게시글을 작성, 공유, 조회하고, 태그와 댓글, 좋아요/싫어요, 업적 시스템을 통해 커뮤니케이션을 즐길 수 있는 웹 애플리케이션입니다.

### 1.2 범위

이 문서는 사이트의 기능 요구사항과 비기능 요구사항을 정의하며, 현재 구현된 설계와 실행 흐름을 반영합니다.

### 1.3 용어 정의

- 사용자(User): 사이트를 이용하는 일반 방문자 또는 로그인 사용자
- 게시글(Post): 제목, 본문, 태그, 이미지, 작성자 정보를 포함하는 글
- 태그(Tag): 게시글 분류 및 검색을 위한 키워드
- 댓글(Comment): 게시글에 대한 사용자 의견
- 좋아요(Like): 게시글에 대한 사용자 반응
- 인증(Authentication): `next-auth` 기반 Google/GitHub 로그인
- 업적(Achievement): 사용자 활동에 따라 부여되는 보상

## 2. 전반적 설명

### 2.1 제품 관점

웹 애플리케이션은 `src/app` 디렉터리 기반 페이지와 `src/app/api/*` API 경로로 구성됩니다. 백엔드 로직은 Next.js API 라우트에서 실행되며, MongoDB에 데이터를 저장합니다.

### 2.2 사용자 유형

- 비회원: 게시글 목록 조회, 게시글 상세 보기, 태그 검색, 익명 댓글 작성
- 회원: 게시글 작성/수정/삭제, 댓글 작성/삭제, 좋아요/싫어요, 내 프로필/설정 조회, 업적 확인
- 관리자(미구현): 별도 역할 모델은 없으나 향후 관리자 기능으로 확장 가능

## 3. 기능 요구사항

### 3.1 인증

- Google/GitHub OAuth 로그인 지원
- `next-auth` 기반 세션 관리
- 로그인 사용자만 게시글 작성, 수정, 삭제, 댓글 작성, 좋아요/싫어요, 프로필/설정 조회 가능

### 3.2 게시글 관리

- 게시글 목록 조회 및 페이징
- 게시글 상세 보기
- 게시글 작성/수정
- 이미지 업로드 후 게시글에 첨부
- 태그 추가/편집
- 게시글 수정 시 `PostRevision`에 이전 버전 저장
- 게시글 삭제 시 soft delete 및 포인트 차감

### 3.3 태그 기능

- 태그 검색 및 자동완성
- 태그 클릭 시 해당 태그가 포함된 게시글 목록 제공
- 태그 목록 전체 조회 지원

### 3.4 댓글 기능

- 게시글에 댓글 작성
- 로그인 사용자 댓글은 `authorId`로 연결
- 비회원은 익명 `anonid` 기반 이름 사용
- 댓글 목록 조회
- 댓글 삭제 권한은 작성자에게만 부여
- 삭제된 댓글은 서버에서 내용이 대체되어 반환됨

### 3.5 좋아요/싫어요

- 게시글 좋아요/싫어요 처리
- 좋아요 수는 0 미만으로 떨어지지 않음
- 추천 상호작용 이후 업적 검증 실행

### 3.6 사용자 대시보드

- 사용자가 본인 글 목록 조회 가능
- 사용자 업적 목록 확인 가능
- 프로필 정보 및 테마 설정 조회/변경 가능

### 3.7 업적 및 포인트

- 새 게시글 작성 시 포인트 부여
- 댓글 작성 시 포인트 부여
- 게시글 작성 수, 댓글 작성 수, 추천 수 달성 시 업적 부여
- 업적 데이터는 `GET /api/my-achievements`로 확인

### 3.8 이미지 업로드

- `POST /api/upload`로 이미지 업로드
- MinIO 또는 S3 호환 저장소 사용
- 썸네일 URL도 함께 저장

## 4. 비기능 요구사항

### 4.1 성능

- 게시글 목록은 페이징 기능으로 처리
- 서버는 MongoDB aggregate로 페이지네이션 및 정렬을 수행
- 이미지 업로드는 비동기적으로 처리

### 4.2 보안

- 인증된 사용자만 민감한 기능 접근 허용
- 서버에서 세션 및 이메일 일치 여부 검증
- 게시글/댓글 삭제 시 작성자 소유권 확인
- Soft delete로 데이터 노출 최소화
- MinIO 환경변수 기반 업로드 설정

### 4.3 유지보수성

- 기능별 파일 구조(`src/app`, `src/components`, `src/lib`, `src/models`) 유지
- 공통 DB 연결 및 도메인 로직 라이브러리 사용
- 모델 중심 스키마 정의로 확장 용이성 확보

### 4.4 접근성

- 키보드 접근성 검토
- 버튼/폼에 적절한 aria 속성 적용 필요
- 리치 에디터 및 리스트 UI의 접근성 개선 필요

## 5. 주요 사용자 시나리오

### 5.1 게시글 탐색

1. 사용자는 홈 페이지 진입
2. 최신 또는 인기 게시글 목록 확인
3. 게시글 클릭 후 상세 내용 확인

### 5.2 태그별 검색

1. 사용자는 태그 페이지 진입
2. 검색어 입력 후 태그 선택
3. 태그 관련 게시글 목록 확인

### 5.3 게시글 작성

1. 사용자는 로그인
2. `app/post/write` 페이지 진입
3. 제목, 본문, 태그 입력
4. 이미지 업로드
5. `POST /api/submit` 호출 후 게시글 저장

### 5.4 게시글 수정

1. 작성자는 본인 게시글 선택
2. 기존 내용을 수정
3. 수정 완료 후 이전 버전은 `PostRevision`에 저장

### 5.5 댓글 작성

1. 사용자는 게시글 상세 페이지에서 댓글 입력
2. 댓글 제출 후 댓글 목록 업데이트
3. 비회원은 익명 ID로 댓글 작성

### 5.6 좋아요 및 업적

1. 사용자는 게시글 좋아요 클릭
2. 좋아요 상태 반영
3. 일정 조건 충족 시 업적 획득

## 6. 제약 조건

- Next.js App Router를 사용하여 SSR/SSG 및 클라이언트 컴포넌트 혼용
- MongoDB + Mongoose 기반 데이터 저장
- 이미지 업로드를 위한 MinIO 또는 S3 호환 저장소 필요
- 인증은 `next-auth` 기반 Google/GitHub 로그인으로 처리
- 게시글/댓글 삭제는 soft delete 방식 사용
- 업적 및 포인트 모델은 현재 점수 기반으로만 동작
